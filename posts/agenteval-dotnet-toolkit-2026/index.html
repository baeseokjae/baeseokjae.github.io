What is AgentEval? — The .NET Evaluation Toolkit for AI Agents#

AgentEval is an open-source, MIT-licensed .NET toolkit for evaluating AI agents, built specifically for the Microsoft Agent Framework (MAF) and Microsoft.Extensions.AI. Created in January 2026 and available on NuGet, it fills a critical gap in the .NET ecosystem: while Python developers had RAGAS and DeepEval for agent evaluation, .NET teams had no dedicated framework — until now. AgentEval provides fluent assertion APIs, stochastic evaluation, workflow testing, model comparison, security red-teaming, and memory benchmarks, all designed to work with any IChatClient provider including OpenAI, Azure OpenAI, Microsoft Foundry, and Ollama.

Why AgentEval Matters — The Non-Determinism Problem in AI Agents#

AI agents are fundamentally non-deterministic. A GPT-4o agent that correctly calls a tool 70% of the time might fail the remaining 30% due to subtle prompt variations, token sampling, or model drift. This unpredictability is not a bug — it is an inherent property of LLMs. OpenAI’s September 2025 paper “Why Language Models Hallucinate” confirmed that even state-of-the-art models produce factually incorrect outputs at non-trivial rates, especially when chaining multiple tool calls.

Traditional unit testing cannot handle this. A test that passes once may fail on the next run for reasons unrelated to code changes. AgentEval addresses this with stochastic evaluation: instead of binary pass/fail, it measures reliability across multiple runs and reports statistical confidence intervals. This is the difference between “the test passed” and “the agent is 95% reliable within a ±2% margin.”

For .NET teams building production AI agents — whether for customer support, code generation, data extraction, or autonomous workflows — AgentEval provides the missing quality assurance layer. Without it, deploying an agent to production is essentially flying blind.

Key Features Deep Dive#

Tool Usage Validation — Fluent Assertions for Agent Tool Chains#

AgentEval’s tool usage validation lets you assert that an agent called the right tools in the right order with the right parameters. The fluent assertion API integrates directly with xUnit, NUnit, and MSTest, providing IntelliSense support in Visual Studio and JetBrains Rider.

var result = await agent.ExecuteAsync("Book a flight to London");
result.Should()
    .HaveCalled("SearchFlights")
    .WithParameter("destination", "London")
    .Then("SelectFlight")
    .WithParameter("flightId", Is.Any<string>())
    .AndNotHaveCalled("CancelBooking");

This chain-based assertion model mirrors how agents actually work — as sequences of tool invocations rather than single-turn responses. You can validate parameter types, value ranges, call order, and explicitly forbid dangerous tool calls. The framework also supports soft assertions that warn rather than fail, useful for exploratory testing during development.

Stochastic Evaluation — Taming LLM Non-Determinism#

Stochastic evaluation is AgentEval’s signature feature. Instead of running a test once and declaring victory, it executes the same evaluation multiple times and aggregates results statistically.

var eval = AgentEval.Evaluate(agent)
    .Repeat(20)  // Run 20 times
    .WithTolerance(0.05)  // 5% margin
    .Assert(reliability => reliability >= 0.85);

This approach reveals the true reliability of an agent. A tool call that works 19 out of 20 times (95%) is very different from one that works 10 out of 20 (50%), and a single test run cannot distinguish between them. AgentEval’s stochastic mode surfaces these differences with statistical confidence, enabling data-driven decisions about model selection, prompt engineering, and guardrail placement.

The framework also supports regression testing across runs: compare the reliability distribution of today’s agent against last week’s baseline to detect regressions introduced by prompt changes, model updates, or code modifications.

Workflow Evaluation — Testing Multi-Agent MAF Flows#

For teams using the Microsoft Agent Framework (MAF), AgentEval provides workflow-level evaluation. Multi-agent systems introduce complexity beyond individual agent correctness — you need to verify executor order, edge traversal, and per-graph tool call patterns.

var workflow = new AgentWorkflow("CustomerSupport")
    .AddAgent("TriageAgent")
    .AddAgent("BillingAgent")
    .AddAgent("EscalationAgent");

var eval = AgentEval.EvaluateWorkflow(workflow)
    .AssertExecutors(executors => executors
        .StartsWith("TriageAgent")
        .ThenAnyOf("BillingAgent", "EscalationAgent"))
    .AssertEdges(edges => edges
        .Traversed("TriageAgent", "BillingAgent")
        .NotTraversed("BillingAgent", "EscalationAgent"));

This is particularly valuable for complex business processes where agent handoff correctness is critical — think insurance claims processing, multi-step customer onboarding, or compliance review pipelines.

Performance SLAs as Executable Evaluations#

AgentEval lets you define performance service-level agreements (SLAs) as executable assertions. Instead of manually timing agent responses, you bake latency and cost constraints directly into your test suite.

var eval = AgentEval.Evaluate(agent)
    .WithSLA(sla => sla
        .MaxLatency(TimeSpan.FromSeconds(5))
        .MaxCost(0.02m)  // $0.02 per call
        .MaxTokens(2000));

When an agent exceeds any SLA threshold, the evaluation fails with a clear diagnostic. This is essential for production deployments where cost overruns or slow responses directly impact user experience and operational budgets. You can also set different SLAs for different agent roles — a triage agent might have a 2-second latency target while a research agent gets 30 seconds.

Behavioral Policy Guardrails — Compliance as Code#

AgentEval’s behavioral guardrails enable compliance-as-code for AI agents. You define policies — PCI-DSS, GDPR, internal safety rules — as executable assertions that run during evaluation.

var policy = AgentEval.CreatePolicy("GDPR")
    .ForbidOutputContaining("social_security_number")
    .RequireOutputContaining("privacy_notice")
    .MaxRetries(3);

var eval = AgentEval.Evaluate(agent)
    .WithPolicy(policy);

This transforms abstract compliance requirements into automated, repeatable checks. When a model update or prompt change introduces a compliance violation, the evaluation catches it before deployment. The policy engine supports regex patterns, exact string matching, semantic similarity thresholds, and custom predicate functions for complex business rules.

Model Comparison — Find the Best Model with Statistical Rigor#

Choosing between GPT-4o, GPT-4o Mini, GPT-3.5 Turbo, or a local Ollama model is not a trivial decision. AgentEval’s model comparison feature runs the same evaluation suite across multiple models and produces a statistical comparison.

var comparison = AgentEval.CompareModels()
    .AddModel("GPT-4o", openAiGpt4o)
    .AddModel("GPT-4o Mini", openAiGpt4oMini)
    .AddModel("GPT-3.5 Turbo", openAiGpt35)
    .AddModel("Llama 3 70B", ollamaLlama3)
    .Evaluate(agent)
    .WithMetric("Tool Accuracy")
    .WithMetric("Relevance")
    .WithMetric("Latency")
    .WithMetric("Cost");

The output is a ranked comparison table showing each model’s performance across all metrics, with confidence intervals. This replaces guesswork with data: you might discover that GPT-4o Mini achieves 96% of GPT-4o’s tool accuracy at 20% of the cost, making it the better choice for high-volume production use.

Getting Started — Installation and First Eval#

Installing AgentEval is straightforward. Add the NuGet package to your .NET project:

dotnet add package AgentEval

AgentEval supports .NET 8, 9, and 10. The CLI tools are installed separately:

dotnet tool install --global AgentEval.CLI

The CLI provides several commands: agenteval init to scaffold a new evaluation project, agenteval bench to run benchmarks, agenteval doctor to diagnose configuration issues, agenteval migrate to update evaluation configurations, and agenteval mc serve to launch the Mission Control portal (requires .NET 10 SDK with Hot Chocolate 16 and MapStaticAssets).

A minimal evaluation with xUnit looks like this:

public class AgentEvalTests
{
    [Fact]
    public async Task CustomerSupportAgent_Should_Use_TriageTool_First()
    {
        var agent = new CustomerSupportAgent(
            ChatClientBuilder.Create()
                .UseOpenAI(apiKey)
                .Build());

        var result = await agent.ExecuteAsync("I have a billing issue");

        result.Should()
            .HaveCalled("ClassifyIssue")
            .WithParameter("category", "billing")
            .Then("RouteToTeam");
    }
}

Jernej Kavka, a Microsoft AI MVP, published a practical tutorial on March 27, 2026, demonstrating how to set up xUnit tests with AgentEval. He discovered the project at the Microsoft MVP Summit and caught production issues in his own agent the same night he integrated it — a testament to the framework’s immediate value.

Running the security suite is a single line:

var securityReport = await AgentEval.SecurityScan(agent)
    .RunAllProbes()
    .GenerateReport();

The report highlights which probes passed, failed, or produced inconclusive results, with detailed explanations of each failure. For .NET teams subject to compliance requirements (SOC 2, ISO 27001, PCI-DSS), this automated security testing provides auditable evidence of agent security posture.

Memory Benchmarks — 5 Metrics for Agent Memory Evaluation#

Agent memory is a critical but often overlooked dimension of agent quality. AgentEval provides 5 dedicated memory metrics:

  1. Recall Accuracy — How accurately does the agent retrieve stored information from previous turns?
  2. Context Retention — Does the agent maintain relevant context across a multi-turn conversation?
  3. Memory Contamination — Does information from one conversation leak into unrelated conversations?
  4. Forgetting Curve — At what point does the agent begin to lose or distort earlier information?
  5. Update Consistency — When memory is updated, does the agent consistently use the new value?

These metrics are essential for any agent that maintains state across interactions — customer support agents that remember past issues, research assistants that build knowledge over sessions, or autonomous agents that persist goals across multiple execution cycles.

var memoryEval = AgentEval.EvaluateMemory(agent)
    .WithScenario("MultiTurnBooking")
    .AssertRecall(accuracy => accuracy >= 0.9)
    .AssertNoContamination();

The Road Ahead — From Preview to Production#

AgentEval is currently in preview status. The project was created on January 2, 2026, and has accumulated 129 GitHub stars and 10 forks as of July 2026 — impressive growth for a 7-month-old project in a niche space. The author, who built AgentEval as a side effect of an auto-investment system project, has been transparent about its experimental status.

Key milestones to watch for:

  • Stable API release — The fluent assertion API is still evolving; breaking changes are possible
  • Expanded OWASP coverage — Currently 6 of 10 categories; the remaining 4 (training data poisoning, supply chain, overreliance, model theft) are likely targets
  • Enterprise features — Role-based access control for Mission Control, team collaboration, audit trails
  • Community growth — More samples, tutorials, and community-contributed probes and policies
  • MAF 2.0 compatibility — As Microsoft Agent Framework evolves, AgentEval will need to keep pace

The project’s open-source nature (MIT license) and active development cadence suggest a stable future, but teams should conduct independent evaluations before relying on it for production-critical workflows.

Verdict — Who Should Use AgentEval in 2026?#

Use AgentEval if:

  • You are building AI agents in .NET with MAF or Microsoft.Extensions.AI
  • You need automated, repeatable evaluation of agent tool usage and reliability
  • You want statistical confidence in agent performance rather than binary pass/fail
  • You require security testing and compliance verification for AI agents
  • You are comparing models and need data-driven selection criteria

Consider alternatives if:

  • Your stack is Python-based (use RAGAS, DeepEval, or MLflow instead)
  • You need a mature, production-hardened framework (AgentEval is still preview)
  • You require LangChain-specific integrations (LangSmith is more mature for that ecosystem)

Bottom line: AgentEval is the most important .NET AI tool you have not heard of yet. It solves a real problem — the lack of .NET-native agent evaluation — with a well-designed, feature-rich toolkit. The stochastic evaluation, security red-teaming, and memory benchmarks are genuinely innovative features that even more mature Python frameworks lack. For .NET teams building AI agents in 2026, AgentEval is not just recommended; it is essential.

FAQ#

What is AgentEval and what does it do?#

AgentEval is an open-source .NET toolkit for evaluating AI agents. It provides fluent assertion APIs for tool usage validation, stochastic evaluation for measuring reliability across multiple runs, workflow testing for multi-agent MAF flows, model comparison with statistical rigor, security red-teaming with 192 probes, and memory benchmarks — all designed for the Microsoft Agent Framework and Microsoft.Extensions.AI ecosystem.

Is AgentEval production-ready?#

AgentEval is currently in preview/experimental status. While it has been battle-tested by the .NET AI community and caught real production issues, the API may still evolve with breaking changes. The project recommends independent review before relying on it for production-critical workflows.

How does AgentEval compare to RAGAS and DeepEval?#

AgentEval is the .NET equivalent of RAGAS and DeepEval, which are Python-only frameworks. AgentEval offers unique features that Python frameworks lack, including stochastic evaluation (measuring reliability across multiple runs), 192 built-in security probes, 5 dedicated memory metrics, and workflow evaluation for multi-agent MAF flows. For .NET teams, AgentEval is the only dedicated option.

What models and providers does AgentEval support?#

AgentEval works with any IChatClient provider, including OpenAI (GPT-4o, GPT-4o Mini, GPT-3.5 Turbo), Azure OpenAI, Microsoft Foundry, and Ollama (Llama 3, Mistral, and other local models). The model comparison feature lets you evaluate the same agent across multiple providers in a single test suite.

How do I get started with AgentEval?#

Install the NuGet package with dotnet add package AgentEval and the CLI tools with dotnet tool install --global AgentEval.CLI. AgentEval supports .NET 8, 9, and 10. The official documentation at agenteval.dev provides a full API reference, and the GitHub repository includes over 30 runnable samples to help you get started quickly.
