Cachebro is an open-source MCP (Model Context Protocol) server that acts as a file cache with intelligent diff tracking for AI coding agents, reducing token consumption by an average of 26% in controlled benchmarks. It intercepts file read requests from tools like Claude Code, Cursor, and OpenCode, serves cached content when files are unchanged, and delivers compact diffs when files have been modified — all without any configuration or changes to how the agent operates.

What is Cachebro?#

Cachebro is a drop-in MCP server built by Glauber Costa, the founder and CEO of Turso. It sits between your AI coding agent and the filesystem, caching every file read and tracking changes using SHA-256 content hashing. When an agent requests a file it has already read, Cachebro serves the cached version instead of re-reading the file from disk. When a file has changed, it computes a diff and sends only the changed lines to the agent.

The core idea is simple: AI coding agents waste a significant portion of their token budget re-reading files they have already seen. Cachebro eliminates this waste by remembering what the agent has already consumed and only sending new or changed content.

Cachebro is distributed as an npm package and implements the Model Context Protocol, meaning any MCP-compatible agent discovers and adopts it automatically. There is no need to modify agent instructions, add tool descriptions, or configure anything beyond a single initialization command.

The Token Waste Problem#

AI coding agents operate on a token budget. Every file they read, every line they process, and every response they generate consumes tokens. In a typical coding session, an agent may read the same file dozens of times — once to understand its structure, again when checking imports, again when verifying a change, and repeatedly across multiple tasks in the same session.

The numbers are striking. In a controlled A/B test on a 268-file TypeScript codebase using Claude Opus, Cachebro reduced total token consumption from 158,248 to 117,188 tokens — a 26% reduction. That is roughly one in every four tokens saved, purely by avoiding redundant file reads.

The waste compounds across sequential tasks. In the same benchmark, the first task saved 2,925 tokens, the second saved 15,571 tokens, and the third saved 35,355 tokens. As the cache warms and the agent works through more files, the savings grow. Over a three-task sequence, Cachebro saved 53,851 cumulative tokens out of 166,526 total consumed — 24% of the entire budget.

For teams running AI coding agents at scale, these numbers translate directly into cost savings. A 26% reduction in token usage means 26% lower API bills, faster task completion, and less context window pressure on the model.

How Cachebro Works#

Cachebro’s architecture is built on three core components: content-addressed caching, diff-on-change detection, and per-session tracking.

SHA-256 Content Hashing#

Every file read by the agent is hashed using SHA-256. The hash serves as a content address — if the file content has not changed, the hash matches the cached entry, and Cachebro returns the cached content without touching the filesystem. This guarantees zero false positives: if the hash matches, the content is identical.

Turso Embedded Database#

Cachebro uses Turso’s embedded database (a SQLite-compatible edge database) as its storage backend. The database stores cached file content, SHA-256 hashes, session state, and diff history. Turso was chosen for its performance characteristics — it is fast enough to serve cached reads with negligible latency while being lightweight enough to embed directly in the MCP server process.

Diff-on-Change Architecture#

When a file has been modified (the SHA-256 hash does not match), Cachebro does not send the entire file. Instead, it computes a diff between the cached version and the current version, sending only the changed lines to the agent. This is where the bulk of the token savings come from — large files with small edits only cost the agent the size of the diff, not the size of the file.

Per-Session Tracking#

Cachebro maintains separate read pointers for each session. This means branch switching works correctly: if an agent switches from one branch to another, Cachebro recognizes that the session state has changed and re-reads files as needed. Each session tracks its own cache state independently, preventing cross-contamination between different agent contexts.

Token Estimation#

Cachebro uses a token estimation formula of ceil(characters * 0.75) to approximate token counts. This is a standard approximation that closely matches the tokenization behavior of most modern LLMs, including Claude and GPT models.

Installation and Setup#

Cachebro is distributed as an npm package and can be installed with a single command.

Quick Start#

npx cachebro init

This command initializes Cachebro in the current directory, creating the necessary configuration and database files. After initialization, Cachebro is ready to use.

Auto-Discovery with MCP Clients#

Because Cachebro implements the Model Context Protocol, MCP-compatible clients discover it automatically. The npx cachebro init command registers Cachebro in the MCP configuration file that tools like Claude Code, Cursor, and OpenCode read on startup.

For Claude Code, Cachebro is picked up automatically after initialization — no additional configuration needed.

For Cursor, Cachebro works through Cursor’s MCP integration. Note that Cursor’s auto-discovery of MCP servers is still evolving, and some users report needing to manually specify the MCP server path in Cursor’s configuration.

For OpenCode and other MCP-compatible agents, the same auto-discovery mechanism applies. If auto-discovery does not work, you can manually add the Cachebro MCP server configuration to your agent’s MCP settings file.

Verifying Installation#

After running npx cachebro init, you can verify that Cachebro is running by checking the cache status:

npx cachebro status

This displays the current cache state, including the number of cached files, total tokens saved, and session information.

MCP Tools Deep Dive#

Cachebro exposes four MCP tools that agents can call. These tools are automatically available to any MCP-compatible agent after installation.

read_file#

The primary tool for reading files. When an agent calls read_file, Cachebro checks its cache:

  • If the file has not changed since the last read, the cached content is returned immediately — no filesystem access, no token cost for re-reading.
  • If the file has changed, a diff is computed and only the changed lines are returned.
  • Supports partial reads with offset and limit parameters, so even large file edits only cost the agent the size of the changed portion.

read_files#

A batch version of read_file that accepts multiple file paths in a single call. This is useful when an agent needs to check several files at once, such as when understanding a module’s dependencies or reviewing a pull request. Each file is independently cached and diffed.

cache_status#

Returns the current state of the cache, including:

  • Number of files cached
  • Total tokens saved
  • Cache hit rate
  • Per-session statistics
  • Database size

This tool is useful for monitoring Cachebro’s effectiveness and understanding how much token waste is being eliminated.

cache_clear#

Resets the cache for the current session. This is useful when the agent needs to re-read files from scratch, such as after a significant refactor or when switching to a completely different context. Cachebro’s per-session design means clearing one session does not affect others.

SDK and Programmatic Usage#

Cachebro includes a TypeScript SDK for developers who want to integrate its caching capabilities into custom tools and workflows.

TypeScript SDK#

The SDK provides programmatic access to Cachebro’s caching engine, allowing developers to:

  • Initialize and manage cache instances
  • Read files through the cache with automatic diff tracking
  • Query cache status and statistics
  • Clear cache entries programmatically
  • Configure cache behavior (session tracking, hash algorithm, storage backend)

Use Cases for the SDK#

The SDK is useful for teams building custom AI coding tools, CI/CD pipelines that use AI agents, or any workflow where file caching with change detection would reduce token consumption. Because Cachebro is MIT-licensed, the SDK can be freely integrated into both open-source and proprietary projects.

Who Built It#

Cachebro was created by Glauber Costa, the founder and CEO of Turso. Costa’s background gives Cachebro unusual credibility for a relatively new open-source project.

Before founding Turso, Costa worked on the Linux Kernel, contributed to ScyllaDB (the high-performance NoSQL database), and served as a Staff Engineer at Datadog. This systems infrastructure background is directly relevant to Cachebro’s design — the tool is built with the same attention to performance, correctness, and reliability that you would expect from someone who has worked on operating systems and distributed databases.

Turso itself is a SQLite-compatible edge database platform, and Cachebro uses Turso’s embedded database as its storage engine. This is not a coincidence — Cachebro serves as both a useful tool in its own right and a demonstration of what Turso’s embedded database can do.

The project has attracted 216 GitHub stars and 19 forks as of August 2026, with 369 monthly npm downloads. It was first released on February 14, 2026, and the latest release is v0.2.2 from May 20, 2026.

Limitations and Open Issues#

Cachebro is a young project (v0.2.2) and has several limitations worth noting.

Windows Support#

Cachebro’s current release has limited Windows support. The initialization command and MCP auto-discovery have been primarily tested on macOS and Linux. Windows users may need to manually configure the MCP server path.

Cursor Auto-Discovery#

While Cachebro works with Cursor through its MCP integration, auto-discovery is not as seamless as with Claude Code. Cursor’s MCP server discovery mechanism is still evolving, and some users report needing to manually specify the Cachebro configuration.

Multi-Chat Support#

Cachebro’s per-session tracking works well for single-agent workflows, but multi-chat scenarios (where multiple agent instances operate in the same workspace) are less tested. Each chat session gets its own cache state, but the interaction between concurrent sessions has not been extensively benchmarked.

Token Estimation Accuracy#

The ceil(characters * 0.75) formula is an approximation. Actual token counts vary by model and tokenizer. While the approximation is close enough for practical purposes, the reported savings may differ slightly from what your specific model reports.

Maturity#

As a v0.2.2 release, Cachebro is still in active development. The API and tool set may change between versions. The project is MIT-licensed and open to contributions, but users should expect some instability as the project matures.

FAQ#

What exactly does Cachebro do for AI coding agents?#

Cachebro acts as a smart file cache between your AI coding agent and the filesystem. It remembers every file the agent has read, serves cached content when files are unchanged, and sends only the changed lines (diffs) when files have been modified. This eliminates the token waste caused by agents re-reading the same files repeatedly.

How much can Cachebro reduce my token usage?#

In controlled benchmarks on a 268-file TypeScript codebase with Claude Opus, Cachebro reduced token consumption by 26% (from 158,248 to 117,188 tokens). Savings compound across sequential tasks — the third task in a sequence saved 35,355 tokens (36% reduction) as the cache warmed.

Does Cachebro require any changes to my agent’s configuration?#

No. Cachebro implements the Model Context Protocol (MCP), so MCP-compatible agents like Claude Code, Cursor, and OpenCode discover and adopt it automatically after running npx cachebro init. No agent instructions, tool descriptions, or workflow changes are needed.

Is Cachebro free and open-source?#

Yes. Cachebro is released under the MIT license, meaning it is free to use, modify, and distribute. The source code is available on GitHub at github.com/glommer/cachebro, and the npm package can be installed with npx cachebro init.

What are Cachebro’s main limitations?#

Cachebro is at version 0.2.2 and has limited Windows support, evolving Cursor auto-discovery, and less-tested multi-chat scenarios. The token estimation formula (ceil(characters * 0.75)) is an approximation that may vary by model. These limitations are expected to improve as the project matures.
