Introduction — What Is Dedalus Labs?#

Dedalus Labs is a Y Combinator S25 startup that provides persistent, full Linux virtual machines for AI agents, booting in under 50 milliseconds and offering root access, GPU support, and per-second billing with free idle time. Founded by Princeton alumni Cathy Di (ex-Voyage AI, Salesforce) and Windsor Nguyen (ex-DeepMind, Sentient AGI), the platform positions itself as the “Vercel for AI agents” — abstracting away the infrastructure complexity of deploying stateful, long-running agents so developers can focus on agent logic rather than server management.

The “Vercel for AI Agents” Thesis#

Why the Vercel Analogy Fits#

Vercel transformed frontend deployment by eliminating server configuration, SSH, and DevOps overhead. Developers pushed code and got a production URL. Dedalus Labs applies the same philosophy to AI agents: instead of provisioning cloud VMs, configuring Docker containers, or stitching together serverless functions, developers write agent code and get a persistent, network-accessible machine that their agent can use for stateful computation, tool execution, and long-running workflows.

The analogy holds across several dimensions:

Where the Analogy Breaks Down#

Dedalus is not a serverless function runner. Its core differentiator is persistence — agents keep state, files, and running processes between invocations. Vercel functions are stateless by design. Dedalus machines are full VMs with root access, SSH, and persistent storage. This makes Dedalus better suited for agents that need to maintain context, run background processes, or interact with the filesystem over extended periods.

Founders and Company Background#

Dedalus Labs was founded in 2025 and participated in Y Combinator’s Summer 2025 batch. The company is headquartered in San Francisco and is actively hiring across six open positions.

Cathy Di brings experience from Voyage AI (an embedding and retrieval startup acquired by Cohere) and Salesforce, where she worked on AI infrastructure at scale. Windsor Nguyen previously worked at DeepMind and Sentient AGI, giving the team deep expertise in both frontier AI research and practical agent deployment. Both founders studied Computer Science at Princeton University.

The YC S25 pedigree, combined with DeepMind and Salesforce experience, provides strong credibility signals. The company has already attracted attention on Hacker News, where their launch post received 77 points and 15 comments, and their Python SDK has accumulated 566 GitHub stars as of July 2026.

Core Product — Dedalus Machines (Persistent VMs for Agents)#

What Are Dedalus Machines?#

Dedalus Machines are lightweight, full Linux virtual machines designed specifically for AI agent workloads. They boot in under 50 milliseconds (the company’s claim) to under 250 milliseconds (independent reviewer measurements), making them suitable for interactive agent applications where latency matters.

Key technical characteristics:

  • Full Linux environment with root/sudo access
  • Persistent storage — data survives between agent invocations
  • SSH access for debugging and direct interaction
  • GPU support for running local models or compute-heavy agent tasks
  • Simple SDKs in Python, TypeScript, and Go — all MIT licensed
  • One API endpoint replaces what the founders describe as “2 weeks of setup with 5 minutes”

The Architecture: Persistent vs Ephemeral#

The fundamental architectural decision that defines Dedalus is persistence. Most serverless platforms (AWS Lambda, Modal, Cloudflare Workers) are ephemeral — functions run, return a result, and the environment is destroyed. This works for stateless APIs but breaks for agents that need to:

  • Maintain conversation history across turns
  • Download and store files
  • Run long background processes
  • Keep database connections alive
  • Cache model weights or embeddings locally

Dedalus machines persist between agent turns. The agent can write files, install packages, start services, and pick up exactly where it left off on the next invocation. This is a fundamentally different programming model from serverless functions and is better aligned with how autonomous agents actually operate.

Boot Speed and Performance#

The sub-50ms boot time (or sub-250ms in practice) is achieved through lightweight VM technology rather than full OS boot. This is comparable to Firecracker microVMs used by AWS Lambda but with persistent storage attached. For agent workloads, this means:

  • An agent can spawn a new machine on demand with minimal latency
  • Machines can be created and destroyed dynamically as workloads scale
  • Idle machines cost nothing (per-second billing with free idle)

The MCP Cloud Platform — SDKs and Tool Ecosystem#

MCP-Native Design#

Dedalus is built from the ground up for the Model Context Protocol (MCP), the emerging standard for connecting LLMs to tools and data sources. Rather than bolting on MCP support as an afterthought, Dedalus treats MCP as its native communication protocol.

The MCP Cloud Platform allows developers to:

  • Upload MCP servers directly to the cloud without Dockerfiles or YAML configuration
  • Connect any LLM to any MCP tool through a single OpenAI-compatible API endpoint
  • Use multi-model fallback with built-in streaming support
  • Monetize tools through the upcoming MCP Marketplace with billing and revenue sharing

The MCP Marketplace (Coming Soon)#

Dedalus is building an MCP Marketplace — a platform where developers can publish, discover, and monetize MCP-compatible tools. If MCP becomes the standard protocol for agent-tool communication (analogous to how HTTP became the standard for web communication), the MCP Marketplace could become a significant platform moat.

The marketplace plans to include:

  • Tool discovery and search
  • Usage-based billing and revenue sharing
  • Authentication and access control (a known gap in MCP — the founders acknowledge “MCP’s ‘S’ stands for ‘security’ ironically”)
  • Version management and compatibility tracking

Cost Comparison#

For a typical agent running 8 hours/day with 50% active compute and 50% idle:

  • Dedalus (4 vCPU, 8 GiB): 4 × $0.04536 × 4hrs + 8 × $0.01458 × 4hrs = $0.725 + $0.467 = ~$1.19/day (idle hours are free)
  • AWS EC2 (t3.medium, similar spec): ~$2.40/day (billed continuously)
  • Modal (serverless): ~$0.80/day (per-second, but no persistent state)

Dedalus is competitively priced for persistent workloads, especially when agents have significant idle time. The free-idle model is a genuine differentiator for agents that sleep between user interactions.

Where Each Competitor Wins#

  • Modal is better for stateless inference workloads, batch processing, and GPU-accelerated compute where persistence is unnecessary.
  • LangGraph excels at complex agent workflow orchestration with state machines, conditional branching, and human-in-the-loop patterns.
  • CrewAI is ideal for multi-agent collaboration scenarios where specialized agents work together on complex tasks.
  • AWS EC2 remains the right choice for traditional workloads, compliance-heavy environments, and teams that need full control over the OS and networking stack.

Dedalus is not a direct competitor to LangGraph or CrewAI — it operates at a different layer of the stack. LangGraph and CrewAI are agent frameworks that run on top of infrastructure. Dedalus is the infrastructure layer. In practice, you could run LangGraph agents on Dedalus machines, combining workflow orchestration with persistent compute.

Developer Experience — Setup, SDKs, and Code Examples#

Getting Started#

The onboarding flow is designed for speed:

# Install the CLI
curl -fsSL https://cli.dedaluslabs.ai/install.sh | bash

# Authenticate
dedalus auth login

# Create a machine
dedalus machine create --name my-agent --spec 2vcpu-4gb

# SSH into it
dedalus ssh my-agent

Python SDK Example#

from dedalus import Dedalus

client = Dedalus()

# Create a machine
machine = client.machines.create(
    name="research-agent",
    spec="4vcpu-8gb",
    gpu=True
)

# Run code on the machine
result = machine.run("""
    import requests
    response = requests.get("https://api.example.com/data")
    return response.json()
""")

print(result)

Connecting an LLM to MCP Tools#

from dedalus import Dedalus
from openai import OpenAI

client = Dedalus()
llm = OpenAI(api_key="...")

# Deploy an MCP server
mcp_server = client.mcp.deploy("my-tools", port=8080)

# Connect any LLM via OpenAI-compatible endpoint
response = llm.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Search the web for AI news"}],
    tools=mcp_server.tools
)

The “5 lines of code” promise is largely accurate for basic use cases. Complex scenarios — multi-machine orchestration, custom networking, GPU workload optimization — require more code, but the abstraction is genuinely thinner than provisioning cloud infrastructure manually.

Strengths and Weaknesses#

Strengths#

  1. Persistent state is a genuine differentiator — Most serverless platforms force stateless architectures. Dedalus’s persistent VMs align naturally with how agents actually work.
  2. Sub-second boot times — The <50ms boot time makes machine creation feel instant, enabling dynamic scaling patterns that aren’t practical with traditional VMs.
  3. Free idle billing — Agents that sleep between user interactions cost almost nothing, making Dedalus economical for conversational and interactive agent use cases.
  4. MCP-native architecture — Betting on MCP as the standard protocol for agent-tool communication positions Dedalus at the center of the emerging agent ecosystem.
  5. YC pedigree and strong founding team — Cathy Di and Windsor Nguyen bring complementary experience from Voyage AI, Salesforce, DeepMind, and Sentient AGI.
  6. Open-source SDKs — MIT-licensed SDKs in three languages reduce vendor lock-in concerns.

Weaknesses#

  1. Early-stage maturity — The platform is new. Documentation, edge cases, and production hardening are still evolving.
  2. MCP Marketplace is not yet live — The platform moat is aspirational rather than realized. Competitors could build similar marketplaces.
  3. Limited geographic regions — As a young startup, Dedalus likely has fewer data center regions than AWS, GCP, or Azure.
  4. Go SDK is immature — With only 34 GitHub stars, the Go SDK is clearly a lower priority and may have gaps.
  5. MCP auth is unresolved — The founders acknowledge that MCP authentication is a known gap, and their solution is “coming next month.”
  6. Vendor lock-in risk — While SDKs are open-source, the core platform is proprietary. Migrating off Dedalus would require re-architecting the infrastructure layer.

Who Is Dedalus For? (Use Cases and Ideal Customer Profile)#

Ideal Use Cases#

  • Conversational AI agents that maintain context across sessions and need persistent memory
  • Research agents that download, process, and store large datasets over extended periods
  • Code generation and execution agents that need a sandboxed environment with root access
  • Automation agents that run scheduled tasks, monitor systems, and maintain state
  • Multi-agent systems where each agent needs its own persistent environment

Who Should Wait#

  • Stateless API wrappers — If your agent is a simple request-response loop with no state, Modal or serverless functions are cheaper and simpler.
  • Compliance-heavy enterprises — If you need SOC 2, HIPAA, or FedRAMP compliance, Dedalus is too early-stage.
  • Teams needing multi-region redundancy — If your workload requires global low-latency deployment, traditional cloud providers offer more regions today.

Verdict — Is Dedalus the Vercel for AI Agents?#

Dedalus Labs makes a compelling case for the “Vercel for AI agents” label. The platform genuinely simplifies agent deployment by providing persistent, fast-booting Linux VMs with per-second billing and free idle time. The MCP-native architecture is a forward-looking bet that could pay off significantly if MCP becomes the standard protocol for agent-tool communication.

The comparison is strongest in the developer experience dimension: Dedalus reduces what used to take days or weeks of infrastructure setup to minutes. The SDKs are clean, the CLI is intuitive, and the “5 lines of code” promise holds for straightforward use cases.

However, Dedalus is not a drop-in replacement for Vercel in the agent world. Vercel succeeded because it sat on top of a mature cloud ecosystem (AWS) and abstracted away complexity without introducing new primitives. Dedalus introduces a new primitive — the persistent agent VM — that doesn’t have an exact analog in the frontend world. This is both its strength (genuine innovation) and its risk (developers need to learn a new mental model).

For developers building stateful AI agents in 2026, Dedalus Labs is worth serious consideration. The pricing is competitive, the technology is innovative, and the founding team has the right background. The biggest open questions are around platform maturity, the MCP Marketplace timeline, and whether the company can execute on its ambitious roadmap before larger players (AWS, Google, Modal) build similar capabilities.

FAQ#

How does Dedalus Labs compare to Modal for AI agent deployment?#

Dedalus provides persistent Linux VMs that maintain state between invocations, while Modal offers ephemeral serverless functions that are destroyed after each run. For stateful agent workloads — where the agent needs to maintain files, running processes, or database connections — Dedalus is the better choice. Modal is better suited for stateless inference, batch processing, and GPU-accelerated compute tasks.

What is the MCP Marketplace and why does it matter?#

The MCP Marketplace is an upcoming platform where developers can publish, discover, and monetize MCP-compatible tools. It matters because if MCP becomes the standard protocol for agent-tool communication, the marketplace could become the primary distribution channel for agent tools — similar to how the Vercel Marketplace or the VS Code extension marketplace created platform ecosystems.

How fast do Dedalus Machines actually boot?#

Dedalus claims boot times under 50 milliseconds. Independent reviewers have measured boot times under 250 milliseconds in practice. Either figure is dramatically faster than traditional cloud VMs (30-60 seconds) and competitive with serverless cold starts. The boot speed enables dynamic machine creation and destruction as agent workloads scale.

What is Dedalus Labs pricing and is it cost-effective?#

Dedalus charges $0.04536 per vCPU-hour and $0.01458 per GiB-hour of memory, with idle time billed at $0. The Hobby tier is free with a $20 one-time credit, and the Pro tier costs $20/month with a $20 monthly compute credit. For agents with significant idle time, the free-idle model makes Dedalus more cost-effective than traditional cloud VMs that bill continuously.

Is Dedalus Labs open source?#

The Dedalus SDKs — available for Python, TypeScript, and Go — are open source under the MIT license. The core platform (the machine infrastructure, MCP cloud platform, and management API) is proprietary. The open-source SDKs reduce vendor lock-in concerns for the client side, but migrating off Dedalus would require re-architecting the infrastructure layer.
