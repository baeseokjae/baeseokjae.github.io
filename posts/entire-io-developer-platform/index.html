Entire.io is an AI-native developer platform founded by former GitHub CEO Thomas Dohmke that raised a $60M seed round in February 2026 to rebuild the software development lifecycle for the age of AI agents. Rather than competing with GitHub directly, Entire positions itself as an abstraction layer that captures, stores, and indexes the full context of AI-assisted development — including every agent session, tool call, and decision — turning ephemeral AI interactions into a permanent, searchable part of the codebase.

What is Entire.io? — Company Overview#

Entire.io is a developer platform built from the ground up for AI-native software development. Founded by Thomas Dohmke, who served as CEO of GitHub from 2021 to 2025, the company raised a $60 million seed round led by Felicis with participation from Madrona, M12 (Microsoft’s venture fund), Basis Set, 20VC, and Cherry Ventures. The round closed in February 2026 and represents one of the largest seed rounds in developer tools history.

The company’s core thesis is straightforward: the current software development lifecycle (SDLC) was designed for human-to-human collaboration and is fundamentally ill-suited for the era of AI-assisted coding. Git, pull requests, code reviews, and issue trackers were all built around the assumption that humans write code, humans review code, and humans deploy code. Entire argues that this model breaks down when AI agents generate 50% or more of new code — a threshold many teams have already crossed.

Entire’s platform consists of three interconnected layers:

  1. A Git-compatible database that stores not just code but the full context of how code was created
  2. A universal semantic reasoning layer that indexes agent sessions, tool calls, and decision trees
  3. An AI-native SDLC that replaces pull requests and manual code reviews with agent-aware workflows

The company’s first public product, Checkpoints, launched as an open-source CLI tool in February 2026. Since then, Entire has also launched a distributed Git hosting network and is building toward a paid platform that combines all three layers.

The Vision: Rebuilding the SDLC for the AI Era#

Dohmke’s central argument, laid out in Entire’s launch blog post, is that the software development lifecycle has become the bottleneck in modern development. “The current SDLC was designed for a world where humans write code, humans review code, and humans deploy code,” he wrote. “That world is rapidly disappearing.”

The problem is structural. When an AI agent like Claude Code or Codex CLI generates a pull request, the traditional review process struggles to answer basic questions: Which parts of this code were AI-generated? What prompt produced this implementation? What alternatives did the agent consider and reject? A human reviewer looking at a 500-line diff from an AI agent has no way to reconstruct the reasoning that produced it.

Entire’s solution is to make the session — not the commit — the fundamental unit of version control. Every time a developer works with an AI agent, Entire captures the full session: every prompt, every tool call, every file edit, every decision point. This session is stored alongside the code in the repository, creating what Entire calls a “semantic memory layer” that preserves not just what changed but why it changed.

This vision has attracted significant talent. Notably, jdx — the creator of the popular mise dev tool — joined Entire.io while continuing his work on mise, signaling that the developer tools community sees promise in Entire’s approach.

Checkpoints — The First Product (Open-Source CLI)#

Checkpoints is Entire’s first public product and the entry point for most users. It is an open-source CLI tool that integrates with existing AI coding agents to capture session data automatically.

How to Install and Use Checkpoints#

Installation is straightforward on macOS via Homebrew:

brew install entireio/tap/entire
entire enable

The entire enable command hooks into supported AI coding agents — currently Claude Code, Codex CLI, Goose, Pi, and OpenCode — and begins capturing session data automatically. Once enabled, every agent session is recorded as a checkpoint, which functions similarly to a Git commit but with dramatically richer metadata.

What Checkpoints Captures#

Each checkpoint stores three key files:

  • metadata.json: Timestamps, agent type, model used, session duration, and file-level change summaries
  • prompt.txt: The exact prompt or instruction that triggered the agent’s actions
  • full.jsonl: A complete JSONL log of every tool call made during the session, including file reads, writes, search queries, and terminal commands

This data structure means that a developer can later ask not just “what files changed?” but “what prompt caused this change?” and “what search queries did the agent run before deciding on this implementation?”

Attribution Tracking#

One of Checkpoints’ most valuable features is attribution tracking. For each commit, Entire breaks down lines of code into three categories:

  • agent_lines: Code written entirely by the AI agent
  • human_added: Lines added manually by the developer
  • human_modified: Lines the developer edited after the agent wrote them

This solves a growing pain point in AI-assisted development: the “who wrote this code” question. When a bug is discovered six months after deployment, knowing whether the code was AI-generated, human-written, or a hybrid can dramatically change the debugging approach.

How Checkpoints Works Under the Hood#

Entire’s engineering team conducted a large-scale analysis of real AI-assisted development sessions to inform Checkpoints’ design. They analyzed 1,983 checkpoints containing 202,142 tool calls from actual development work. The findings are revealing:

  • 48.8% of all tool calls are search-related — that’s 98,555 search calls out of 202,142 total
  • The majority of agent time is spent reading and searching existing code, not writing new code
  • Better-ranked search results improve first-query retrieval more than raw search speed

This data drove a key design decision: Checkpoints must prioritize search and retrieval performance. Because nearly half of all agent activity is search, the platform’s ability to index and surface relevant context from past sessions directly impacts developer productivity.

The checkpoint data structure is designed for this use case. By storing every tool call in a structured JSONL format, Entire can build semantic search indexes over billions of checkpoints. When an agent starts a new task, it can search past sessions for similar problems, relevant code patterns, and prior decisions — effectively giving the agent access to the team’s collective development history.

The Distributed Git Network#

In July 2026, Entire launched a distributed Git hosting network — a significant expansion beyond the Checkpoints CLI. The network consists of nodes deployed in three regions: the United States, the European Union, and Australia.

Why Distributed?#

The motivation is practical. Centralized Git hosting (GitHub, GitLab) creates a bottleneck for agent-scale traffic. When hundreds or thousands of AI agents are cloning repositories, fetching branches, and pushing commits simultaneously, centralized rate limits and geographic latency become serious constraints.

Entire’s distributed network addresses this in several ways:

  • Regional cells: Agents fetch from the nearest Entire node rather than a single global server
  • GitHub mirroring: Entire mirrors GitHub repositories so agents can access them without hitting GitHub’s rate limits
  • Entire-native branches: Support for higher concurrency through specialized branch handling
  • Waitlisted access: New users are waitlisted for capacity management, indicating strong early demand

Early testing shows competitive performance compared to Cursor’s infrastructure, though Entire has not published detailed benchmarks.

Digital Sovereignty#

A secondary but important feature of the distributed network is data residency. Entire’s regional node architecture means that code and session data can remain within specific geographic boundaries — a critical requirement for enterprise customers in regulated industries like finance, healthcare, and government.

Dohmke has framed this as “digital sovereignty,” arguing that Git must return to its original promise of decentralization. “Git was designed as a distributed system,” he wrote. “Centralized hosting was a convenience, not a feature. As we enter the agent era, we need to return to Git’s distributed roots.”

Entire Blame and Other Features#

Beyond Checkpoints and the distributed Git network, Entire is building several additional features that extend the concept of AI-aware version control.

Entire Blame is a reimagining of git blame for the AI era. Instead of showing who last modified each line, Entire Blame shows how each line was created — whether by an agent, a human, or a human editing agent output. It also links back to the specific session and prompt that produced the change, giving developers a complete audit trail.

Semantic search over checkpoints is another key feature. Because every session is indexed with full tool-call data, developers can search across all past agent sessions for specific patterns, decisions, or implementations. This turns the repository from a static code archive into a searchable development history.

Agent-aware workflows are the longer-term vision. Entire aims to replace the traditional pull request workflow with something more suited to AI-assisted development: automated review of agent-generated code, conflict resolution at the session level, and continuous integration that understands the difference between human and AI contributions.

Entire.io operates in a space that is rapidly evolving. Several tools and projects address overlapping problems, though none offer the full platform vision that Entire is pursuing.

Claudit is a community tool that provides basic session logging for Claude Code. It captures prompts and responses but lacks the structured data model, distributed infrastructure, and semantic search that Entire offers.

Agent-Rules takes a different approach, focusing on prompt-level rules and guidelines for AI agents rather than session capture. It’s useful for standardizing agent behavior but doesn’t address the version control or attribution problems.

agentblame is a lightweight tool that adds AI attribution to git blame output. It solves the “who wrote this” question at the line level but doesn’t capture session context or provide search capabilities.

Entire’s competitive advantage lies in its comprehensive approach: session capture, attribution, distributed hosting, and semantic search are all part of a single platform rather than separate tools that need to be stitched together.

HN Community Reception — 611★ and the Skeptics#

Entire’s Hacker News launch thread accumulated 611 points and 114 comments — a strong reception by HN standards, though the sentiment was notably mixed.

The Enthusiasts#

Supporters of Entire’s vision argue that the problem it addresses is real and growing. As AI agents write more production code, the inability to trace, audit, and understand AI-generated changes becomes a liability. Teams that have adopted AI coding tools at scale report exactly the pain points Entire describes: difficulty reviewing AI-generated PRs, inability to reproduce agent behavior, and uncertainty about code provenance.

The involvement of Thomas Dohmke — who led GitHub through its Copilot launch and the AI coding revolution — lends credibility to the thesis. If anyone understands the future of developer platforms, the argument goes, it’s the person who ran the largest code hosting platform during the most transformative period in its history.

The Skeptics#

Critics raised several concerns on the HN thread:

  1. Complexity: Adding another layer of tooling on top of an already complex development stack. Developers already juggle Git, CI/CD, package managers, and multiple AI agents. Does the world need another CLI tool?

  2. Adoption friction: Checkpoints requires developers to opt in and configure it. For teams that aren’t already heavy AI agent users, the value proposition is unclear.

  3. Long-term monetization: The open-source CLI is free, but Entire’s paid platform is not yet available. Skeptics question whether the company can convert open-source users into paying customers.

  4. GitHub’s response: GitHub is not standing still. With Copilot, GitHub Models, and ongoing platform investments, Microsoft-backed GitHub could potentially build similar capabilities.

  5. Early stage: Checkpoints is Entire’s only public product. The distributed Git network is waitlisted. The semantic search and agent-aware workflows are still in development. The company is betting on a vision that has not yet been fully delivered.

Verdict — Is Entire.io the Future of GitHub?#

Entire.io is not a GitHub competitor in the traditional sense. It does not aim to replace GitHub as a code hosting platform. Instead, it positions itself as an abstraction layer that sits on top of GitHub (and potentially other hosts) to provide AI-native capabilities that GitHub does not offer.

The question is whether this abstraction layer is necessary or whether GitHub will build equivalent functionality into its own platform. Dohmke’s argument — that GitHub’s existing architecture and business model make it difficult to pivot to an AI-native model — has merit. Large platforms face genuine innovation challenges when their existing products and revenue streams are built on a different paradigm.

For early adopters — teams already using AI agents extensively in their development workflow — Entire offers immediate value. Checkpoints provides visibility into agent behavior that is simply not available through any other tool. The attribution tracking alone can save hours of debugging time when questions arise about code provenance.

For the broader market, Entire’s success will depend on execution. The vision is compelling, but the company is early-stage with a single public product. The distributed Git network, semantic search, and agent-aware workflows are promising but unproven at scale.

The $60M seed round gives Entire the runway to build its platform and find product-market fit. The involvement of investors like Felicis and M12 (Microsoft’s venture arm) suggests that sophisticated backers see the potential. And Dohmke’s track record at GitHub provides founder-market fit that few startups can match.

Bottom line: Entire.io is the most ambitious attempt yet to rebuild developer tooling for the AI era. It is worth watching — and for teams deep in AI-assisted development, worth trying today.

Frequently Asked Questions#

What is Entire.io and how does it work?#

Entire.io is an AI-native developer platform founded by former GitHub CEO Thomas Dohmke. It captures, stores, and indexes the full context of AI-assisted development sessions — including prompts, tool calls, and file edits — and stores them alongside code in a Git-compatible database. Its first product, Checkpoints, is an open-source CLI that integrates with AI coding agents like Claude Code and Codex CLI.

How does Entire Checkpoints differ from regular Git?#

Regular Git captures what changed in a codebase (the diff). Entire Checkpoints captures why it changed — the full session context including the prompt that triggered the change, every tool call the agent made, and the decision tree the agent followed. Checkpoints stores this as structured metadata alongside the code, creating a searchable development history.

Is Entire.io a GitHub competitor?#

No. Entire.io positions itself as an abstraction layer on top of GitHub, not a replacement. It mirrors GitHub repositories and adds AI-native capabilities that GitHub does not offer, such as session capture, attribution tracking, and semantic search over agent interactions. Entire’s distributed Git network also provides regional caching for faster agent access.

Which AI coding agents does Entire support?#

Entire currently supports five AI coding agents: Claude Code (by Anthropic), Codex CLI (by OpenAI), Goose, Pi, and OpenCode. The Checkpoints CLI hooks into these agents automatically when enabled with the entire enable command. Support for additional agents is expected as the platform matures.

How much does Entire.io cost?#

Checkpoints, the open-source CLI, is free to use. Entire’s distributed Git network and upcoming platform features are currently waitlisted, and pricing has not been announced. The company raised a $60M seed round and is expected to introduce paid tiers for its platform services once they exit beta.
