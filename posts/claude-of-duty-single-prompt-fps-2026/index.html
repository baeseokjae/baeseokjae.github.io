Claude of Duty: Building a Call of Duty-Quality FPS from a Single Prompt with AI

Claude of Duty proves AI agents can generate a 55,000-line FPS from one prompt. We analyze the architecture, performance, and what it means for game development.

What is Claude of Duty?#

Claude of Duty is an open-source experiment by Matt Shumer (CEO of OthersideAI) that proves a single prompt can generate a complete first-person shooter rivaling Call of Duty in scope. The project consists of approximately 55,000 lines of JavaScript across 11 subsystems, all produced by AI agents with zero external art assets, textures, or audio files. The only runtime dependency is Three.js r180.

How Did a Single Prompt Generate 55,000 Lines of Game Code?#

The project began with a single ambitious prompt: “I want you to build a first-person shooter at the level of the most recent Call of Duty games.” From that starting point, AI agents orchestrated the creation of 11 interconnected subsystems that together form a playable browser-based FPS. The prompt itself is documented in the repository’s prompt.md file, and the entire codebase was generated through iterative AI agent passes rather than manual programming.

The key insight is that the AI did not write 55,000 lines in one shot. Instead, it used a sequential, single-owner approach where one AI agent maintained context across multiple passes, building subsystems one at a time while preserving coherence across the entire codebase. This approach proved dramatically more effective than parallel fan-out, where multiple agents work simultaneously on different parts.

Each subsystem was generated by AI agents working in sequence, with the renderer and physics systems being the most technically demanding. The custom physics engine handles 29,000 triangles converted into 14,000 BVH nodes in just 22 milliseconds, with raycasts completing in 0.25 microseconds.

How Does Claude of Duty Perform in Practice?#

Performance is where the project’s AI-generated nature becomes most apparent. On Apple Silicon hardware at 1512x982 resolution with Retina DPR, the game achieves 28-30 fps at the 50th percentile and 14-17 fps at the 99th percentile after optimization. Before optimization, performance was significantly worse: 12-17 fps p50 with worst-frame stalls of 728-1,236 milliseconds caused by over 34 lazy WebGL shader compilations.

The optimization pass was remarkably effective: it reduced boot time by roughly 60%, eliminated all mid-frame shader compilations, and doubled the average framerate. This was achieved primarily through shader pre-warming — compiling all shaders during the loading screen rather than lazily during gameplay.

What Score Did Adversarial Critics Give It?#

The project’s README includes one of the most refreshingly honest self-assessments in open-source history. Matt Shumer implemented an adversarial critic system where human evaluators compared Claude of Duty against real Call of Duty gameplay. The results were sobering:

  • Average score: 5.05 out of 10 — a failing grade by any reasonable standard
  • Blind A/B testing: Real Call of Duty won every single round — no critic ever picked Claude of Duty over the genuine article

This honesty is a deliberate design choice. Rather than overhyping the project, Shumer presents the data transparently, which paradoxically makes the achievement more impressive. A game that scores 5/10 against Call of Duty — generated entirely from a single prompt with no art assets — is remarkable. The fact that the creator admits the gap honestly builds far more trust than exaggerated claims ever could.

Why Does Sequential AI Orchestration Beat Parallel Approaches?#

The most valuable finding from the Claude of Duty project may not be the game itself but the insight about AI agent orchestration. The project compared two approaches:

Sequential single-owner passes: One AI agent maintains context across multiple improvement passes, building subsystems in order and preserving coherence.

Parallel fan-out: Multiple AI agents work simultaneously on different subsystems, then attempt to merge results.

The results were decisive:

MetricSequentialParallel
Score improvement+1.00+0.46
Defects introduced2666
CoherenceHigh — systems integrate naturallyLow — integration issues common

Sequential single-owner passes produced twice the score improvement with less than half the defects. This makes intuitive sense: game code is deeply coupled. The renderer must know how the physics system positions objects. The player controller must integrate with the weapon system. When multiple agents work in parallel without shared context, integration bugs multiply.

For developers building AI-assisted software, this finding has profound implications. The optimal strategy is not to throw more AI agents at a problem but to use one agent with sustained context across sequential passes. Quality of context beats quantity of parallel workers.

What Does This Mean for the Future of Game Development?#

Claude of Duty represents a significant milestone in AI-assisted game development, but it is important to understand both what it enables and what it does not yet solve.

Procedural Generation at Scale#

The project demonstrates that AI can generate every visual and audio asset procedurally. The 19 procedural PBR surfaces — concrete, brick, plaster, asphalt, sand, rusted metal, painted metal, brushed metal, wood, fabric, burlap, glass, and more — are all generated mathematically at load time. The weapon models are procedural geometry. The audio is synthesized through Web Audio API. This eliminates the traditional asset pipeline entirely.

Rapid Prototyping#

For game designers, Claude of Duty shows that AI can produce a playable prototype from a single sentence. A concept that would traditionally require a team of 5-10 people working for weeks can now be generated in hours. This dramatically lowers the barrier to testing game mechanics and level designs.

The Gap Remains Large#

Despite the technical achievement, the 5.05/10 score and the unanimous blind A/B results show that AI-generated games are not yet competitive with human-crafted experiences. The gap is in:

  • Artistic direction: Procedural textures lack the intentional design of hand-crafted art
  • Game feel: Physics and controls feel different from carefully tuned commercial games
  • Content density: A 120x120m level is tiny compared to modern Call of Duty maps
  • Polish: The 14-17 fps p99 performance means noticeable stuttering during action

The Tooling Contribution#

Arguably, the most valuable output of the Claude of Duty project is not the game but the tooling infrastructure built alongside it. The capture/baseline/imagediff system for reproducible testing — which allows developers to take automated screenshots, compare them against baselines, and detect visual regressions — is a production-quality testing framework that could benefit any WebGL project.

The Verdict: Is Claude of Duty Actually Good?#

The honest answer is nuanced. As a game to play, Claude of Duty is not good — it scores 5/10 against real Call of Duty, and no critic preferred it in blind testing. The performance, while improved, still falls short of smooth gameplay, and the procedurally generated world lacks the intentional design of hand-crafted levels.

As a technical demonstration, Claude of Duty is extraordinary. It proves that:

  • AI agents can generate 55,000 lines of coherent, interconnected game code
  • A single prompt can produce a playable FPS with 11 subsystems
  • Procedural generation can replace an entire art and audio asset pipeline
  • Sequential AI orchestration dramatically outperforms parallel approaches

For game developers, AI researchers, and anyone interested in the future of software generation, Claude of Duty is essential reading. The project’s GitHub repository has already accumulated over 1,000 stars and 210 forks in its first three days, reflecting the community’s recognition of its significance.

For players looking for a Call of Duty experience, stick with the real thing. But for anyone wondering what AI-assisted game development looks like in 2026, Claude of Duty is the most honest and informative case study available.

Frequently Asked Questions#

Can I play Claude of Duty in my browser right now?#

Yes. Claude of Duty runs entirely in the browser using Three.js and WebGL2. You can clone the repository from GitHub and run it locally with a simple HTTP server. There are no external assets to download — everything generates procedurally at load time.

How long did it take AI agents to generate the entire game?#

The project does not specify exact generation time, but the sequential single-owner approach involved multiple passes over several subsystems. The key finding is that sequential passes with sustained context produce better results than parallel approaches, even if they take longer in wall-clock time.

What hardware do I need to run Claude of Duty?#

The game was tested on Apple Silicon hardware at 1512x982 resolution with Retina DPR. It achieves 28-30 fps p50 after optimization. Performance on lower-end hardware or non-Apple devices has not been documented, but the WebGL2 renderer should work on any modern GPU.

Is the code production-quality or just a prototype?#

The code is best described as a functional prototype. While it demonstrates impressive technical depth — including a custom BVH physics engine, HDR rendering pipeline, and procedural material system — the 5.05/10 score and performance limitations indicate it is not production-ready for commercial game development.

What is the most important lesson from Claude of Duty for AI developers?#

The most important lesson is that sequential single-owner AI passes produce dramatically better results than parallel fan-out for coupled systems. Sequential passes achieved +1.00 score improvement with 26 defects, while parallel approaches managed only +0.46 with 66 defects. For any complex, interconnected software project, maintaining context across sequential iterations is more valuable than parallel execution speed.
