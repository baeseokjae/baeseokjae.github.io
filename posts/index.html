It ships the operational layer instead: a daemon that forks each agent as its own OS process, a centralized tool registry with manifest-based authorization, MCP and sandbox routing, credential isolation, and OpenTelemetry spans. It is pre-1.0, single-author, and has 3 stars. That is the whole verdict in one paragraph. The interesting question is not “is gogent popular” — it is not, and the numbers are unambiguous — but whether the layer it occupies is a real gap in the Go ecosystem. Eino, Google’s ADK for Go, Genkit and tRPC-Agent-Go are all in-process libraries that own your agent loop. gogent refuses to, and instead owns the process model around it.
