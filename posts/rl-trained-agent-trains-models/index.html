What Is an RL-Trained Agent That Trains Models with RL?#

An RL-trained agent that trains models with RL is a meta-reinforcement learning system where one AI agent — itself trained via reinforcement learning — learns to write and execute RL training jobs for smaller language models. This nested architecture, demonstrated in the open-source “AI Trains AI” project, uses two GRPO (Group Relative Policy Optimization) loops stacked on top of each other: an outer loop that trains a trainer agent using Thinking Machines’ Tinker API, and an inner loop where that agent spawns prime-rl GRPO training runs for small Qwen models on rented Runpod GPUs. The entire pipeline ran for approximately $1,275, proving that recursive self-improving AI training is accessible to individual developers.

The Architecture: Two Nested RL Loops#

The system is built on a simple but powerful insight: if reinforcement learning can train a model to solve math problems, it can also train a model to write RL training scripts. The architecture separates concerns into two distinct loops that communicate through a shared job queue.

The outer loop runs on Tinker’s managed RL infrastructure, which handles importance-sampling GRPO with async off-policy support. Each outer-loop step generates a batch of ~40 real GPU training jobs, evaluates the resulting models, and feeds the reward signal back to improve the trainer agent. Over 54 outer-loop steps, the system executed approximately 1,750 individual GPU training jobs.

Outer Loop — The Trainer Agent (Qwen3.6-35B-A3B + Tinker GRPO)#

The trainer agent is a Qwen3.6-35B-A3B model fine-tuned with LoRA adapters via Tinker’s GRPO implementation. Tinker is Thinking Machines’ managed RL API that provides importance-sampling GRPO with async off-policy support — meaning the agent can learn from training jobs that were launched with older versions of its policy, dramatically improving sample efficiency.

The agent’s action space includes:

  • Base model selection: choosing between Qwen 0.6B and Qwen 1.7B for each inner-loop training job
  • Hyperparameter configuration: setting learning rate, batch size, GRPO group size, and other training parameters
  • Task family selection: picking which task distribution to train the inner model on

Tinker’s pricing model is token-based: $0.36 per million prefill tokens, $0.89 per million sample tokens, and $1.07 per million train tokens. The total Tinker cost for the headline arc was approximately $465.

Inner Loop — Training Small Models (prime-rl GRPO on Runpod GPUs)#

The inner loop uses Prime Intellect’s prime-rl framework (1,692 GitHub stars) to train small Qwen models (0.6B and 1.7B parameters) using GRPO. Each training job runs on a warm Runpod GPU pod, with the orchestrator managing a fleet of up to 16 concurrent pods.

The GPU fleet composition was:

  • A40 (64%): Primary workhorse, reliable and cost-effective
  • RTX 4090 (32%): Higher throughput when available
  • RTX A6000 (3%): Occasional high-memory jobs
  • RTX A5000 (1%): Rare fallback

Each inner training job cost between $0.13 and $0.30 depending on GPU availability and job duration. An entire outer-loop batch — 40 real GPU jobs plus agent inference tokens — cost approximately $15 to $23 all-in.

The Reward Design That Made It Work#

Reward design is the critical challenge in any RL system, and doubly so in a nested RL setup. The project used Prime Intellect’s verifiers library (4,387 GitHub stars) to define task families and compute rewards for the inner-loop models.

Each task family consists of programmatic verifiers that check model outputs against ground-truth rubrics. The trainer agent’s reward is computed from the aggregate performance of the models it trains — if the inner models improve, the trainer gets a positive reward signal.

The reward function had two implicit phases that emerged naturally during training:

  1. Process reliability: The agent first had to learn to produce training jobs that didn’t crash — valid configurations, correct API calls, proper checkpointing
  2. Genuine improvement: Once jobs ran reliably, the reward signal reflected actual model quality gains

This two-phase emergence was not explicitly programmed. It arose from the GRPO optimization dynamics, and it represents a key insight for anyone building similar systems.

Rung 1 — Process Reliability#

In the first ~20 outer-loop steps, the agent learned the mechanical skills of running training jobs. It discovered that the 1.7B model produced better results than the 0.6B model and shifted its selection rate from 42% to over 80%. It learned to explore the hyperparameter space — surface usage jumped from 21% to approximately 60%. Most importantly, it learned to produce valid training configurations that didn’t fail during execution.

This phase is critical because it mirrors what any human ML engineer goes through: before you can optimize model quality, you need a reliable training pipeline. The agent learned this without explicit instruction, purely from the reward signal.

Rung 2 — Genuine Model Improvement#

Once the agent could reliably execute training jobs, the reward signal began reflecting actual model quality. Episode reward climbed from approximately 0.0 to a peak of 0.63 at step 40, then settled to around 0.55 by step 54. The slight decline after the peak is consistent with GRPO’s exploration dynamics — the agent continued trying new strategies, some of which underperformed, but the overall trajectory was upward.

The agent’s hyperparameter surface usage reached approximately 78%, meaning it was actively tuning most available knobs rather than relying on defaults. This is a strong signal that the agent was genuinely optimizing rather than exploiting a single fixed configuration.

Transfer Learning to Held-Out Tasks#

The most compelling evidence that the agent learned a real skill comes from the transfer learning evaluation. A held-out task family — one the agent never trained on — was used to measure generalization.

The transfer reward improved from 0.399 to 0.545 at step 34, a 37% relative improvement. The fact that the agent generalized to an unseen task family proves it learned a genuine skill — how to train models effectively — rather than overfitting to the training distribution. The plateau and slight decline after step 34 suggest the agent began specializing to the training tasks, but the transfer gain was durable.

Infrastructure and Cost Breakdown ($1.3K)#

The total cost of the headline training arc was approximately $1,275, making it one of the most cost-effective demonstrations of recursive RL training.

Each outer-loop batch cost $15–$23, covering 40 GPU training jobs plus the agent’s inference and training tokens on Tinker. The warm pod fleet strategy — keeping up to 16 GPUs warm with bootstrap-pinned software revisions — eliminated cold-start delays and kept per-job costs predictable.

The project is fully open source, including LoRA adapter weights on HuggingFace, the agent harness code, task family definitions, reward computation scripts, GPU orchestration code, and detailed retrospective write-ups of every failure and blind alley encountered during development.

How to Get Started (Open Source Repo + Weights)#

The entire project is available on GitHub at github.com/Danau5tin/ai-trains-ai. The repository includes:

  • Agent harness: The outer-loop training code that interfaces with Tinker
  • prime-rl integration: Configuration files for the inner-loop training stack
  • Task families: The verifier-based environments used for training and evaluation
  • GPU orchestration: Scripts for managing the Runpod fleet
  • LoRA adapters: Fine-tuned weights hosted on HuggingFace

To replicate the setup, you need:

  1. A Tinker API key for the outer-loop RL training
  2. A Runpod account with API access for GPU pods
  3. Python 3.10+ with the prime-rl and verifiers libraries installed

The project’s README includes step-by-step setup instructions, and the retro write-ups document every failure mode encountered — from API rate limits to GPU allocation races to reward hacking attempts.

Key Takeaways for AI Practitioners#

Nested RL is practical at small scale. The $1.3K price tag proves that recursive self-improving AI training is not limited to well-funded labs. Individual developers and small teams can experiment with meta-RL pipelines.

Process reliability precedes model quality. The two-phase learning dynamic — where the agent first learns to run valid jobs, then optimizes for quality — is a natural consequence of GRPO optimization. Practitioners should expect this and design their reward functions accordingly.

Transfer learning validates the approach. The held-out task improvement from 0.399 to 0.545 confirms the agent learned a generalizable skill, not a memorized recipe. This is the strongest evidence that nested RL training produces real capability.

Open infrastructure enables reproducibility. The combination of Tinker (managed RL), prime-rl (training framework), verifiers (evaluation), and Runpod (compute) creates a fully replicable stack. Every component is available as a service or open-source library.

Future Directions: Iterative Experimentation and Richer Tasks#

The current demonstration is a proof of concept, but the architecture scales naturally. Future work could explore:

  • Larger base models: The trainer agent (Qwen3.6-35B-A3B) could be scaled up, or the inner-loop models could be trained on larger architectures
  • Richer task families: The current task families are programmatic verifier environments; expanding to code generation, reasoning chains, or multimodal tasks would test the limits of the approach
  • Longer training horizons: The 54-step arc showed signs of continued improvement; longer runs with more compute could reveal whether the agent continues to improve or plateaus
  • Multi-agent variants: Multiple trainer agents competing or collaborating could accelerate discovery of optimal training strategies

The project has already attracted significant community interest — 107 points and 48 comments on Hacker News, and 199 GitHub stars at the time of writing. The prime-rl and verifiers frameworks have 1,692 and 4,387 stars respectively, indicating a growing ecosystem around agentic RL training.

FAQ#

Q1: What exactly does an RL-trained agent that trains models with RL do? It is a meta-reinforcement learning system where one AI agent, itself trained via RL, learns to write and execute RL training jobs for smaller language models. The agent selects base models, configures hyperparameters, and manages GPU training runs — all optimized through a nested GRPO reward signal.

Q2: How much does it cost to run this pipeline? The headline training arc cost approximately $1,275 total — $810 for Runpod GPU pods and $465 for Tinker managed RL API tokens. Each outer-loop batch of 40 GPU training jobs cost $15–$23 all-in, and individual inner-loop training jobs cost $0.13–$0.30 each.

Q3: What is GRPO and why is it used in both loops? GRPO (Group Relative Policy Optimization) is a reinforcement learning algorithm that trains models by comparing groups of outputs rather than requiring a separate critic model. It is used in both loops because it is sample-efficient, stable, and well-suited for training with programmatic verifiers — making it ideal for nested RL architectures.

Q4: Did the agent actually learn to train models better, or did it just memorize a recipe? The transfer learning results prove the agent learned a genuine skill. When evaluated on a held-out task family it never trained on, the mean reward improved from 0.399 to 0.545 — a 37% relative gain. This generalization to unseen tasks confirms the agent learned how to train models effectively, not just a fixed recipe.

Q5: Can I replicate this project myself? Yes. The entire project is open source on GitHub at github.com/Danau5tin/ai-trains-ai, including the agent harness, task families, GPU orchestration scripts, and LoRA adapter weights on HuggingFace. You need a Tinker API key, a Runpod account, and Python 3.10+ with the prime-rl and verifiers libraries.
