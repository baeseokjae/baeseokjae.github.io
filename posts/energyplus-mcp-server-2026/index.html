EnergyPlus MCP servers bridge the gap between AI assistants and building energy simulation by exposing EnergyPlus models, simulation runs, and results through the Model Context Protocol (MCP). These servers let you load, inspect, modify, and simulate building energy models using natural language commands from any MCP-compatible client — Claude Desktop, VS Code, Cursor, or custom applications. In 2026, the ecosystem has matured from a single academic prototype to multiple production-ready implementations, with the LBNL EnergyPlus-MCP (109 GitHub stars, published in SoftwareX 2025) and idfkit-mcp (37 tools across 10 categories) leading the field.

What Is EnergyPlus MCP Server?#

An EnergyPlus MCP server is a lightweight software layer that implements the Model Context Protocol to connect AI assistants with EnergyPlus — the U.S. Department of Energy’s flagship building energy simulation engine. Instead of writing Python scripts or manually editing IDF files, you can ask an AI assistant to load a model, change a window-to-wall ratio, run a simulation, and plot the results, all through structured tool calls.

The architecture follows a layered design: the MCP Protocol layer handles client communication, a Tools layer exposes 30–37 structured operations, an Orchestration layer sequences multi-step workflows, and the EnergyPlus Integration layer wraps the native EnergyPlus engine via libraries like eppy. This design means the AI assistant never touches EnergyPlus directly — it calls tools, and the MCP server translates those calls into valid EnergyPlus operations.

Why Use MCP for Building Energy Simulation?#

Traditional EnergyPlus workflows require deep knowledge of IDF syntax, Python scripting with eppy, and manual file management. MCP servers eliminate these barriers in several ways.

Natural language model editing. You can tell an AI assistant “change the roof insulation to R-38” and the MCP server handles the IDF modification, validation, and confirmation. No need to remember the exact EnergyPlus object name or field order.

Automated simulation pipelines. Running parametric studies — varying window sizes, orientation, insulation levels — becomes a single conversation instead of a batch script. The MCP server manages model copies, runs simulations, and aggregates results.

Real-time visualization. Several MCP servers include geometry viewers, schedule heatmap viewers, and plot generators. You can ask “show me the cooling load profile” and get an interactive Plotly chart without exporting CSV files.

AI-driven optimization. The most transformative use case is autonomous building optimization. The EcoLoop project demonstrated 8.5% HVAC energy savings using closed-loop control with EnergyPlus and MCP. The AegisOS multi-agent system achieved 58.24% energy reduction using LLM-based HVAC optimization with MCP tool-calling. These results show that MCP is not just a convenience layer — it enables entirely new capabilities in building energy management.

Top EnergyPlus MCP Server Options in 2026#

1. LBNL-ETA/EnergyPlus-MCP (The Original)#

Developed by Lawrence Berkeley National Laboratory, this is the first open-source MCP server for EnergyPlus. It offers 35 tools across 5 categories: Model Config/Loading, Model Inspection, Model Modification, Simulation & Results, and Server Management. Published in SoftwareX journal (Volume 32, 2025, DOI: 10.1016/j.softx.2025.102367), it carries academic credibility and is backed by DOE research.

The server ships with EnergyPlus 26.1.0 pre-installed in its Docker image and supports deployment via Docker, pip, or source. It works with Claude Desktop, VS Code, Cursor, and MCP Inspector. The license is BSD-3-Clause-LBNL, and the project has 109 GitHub stars and 24 forks as of August 2026.

Key dependencies include mcp, eppy, matplotlib, networkx, pandas, plotly, and graphviz — making it a full-stack solution for model manipulation, simulation, and visualization.

2. idfkit/idfkit-mcp (Most Feature-Rich)#

idfkit-mcp is the most comprehensive EnergyPlus MCP server available, offering 37 tools across 10 categories plus 13 MCP resources for read-only data access. Its standout feature is support for 17 EnergyPlus versions — from 8.9 through 26.1 — with bundled schemas for each version. This makes it the best choice for users with legacy models who cannot upgrade to the latest EnergyPlus release.

The server is pip-installable (pip install idfkit-mcp or uv add idfkit-mcp) and built on the idfkit library for robust EnergyPlus model handling. It supports IDF, epJSON, and OSM file formats, includes schema exploration, model editing, validation, simulation, weather search, geometry viewer, and schedule heatmap viewer. Session state persists to disk automatically, and a Docker image with EnergyPlus bundled is available. Licensed under MIT with comprehensive documentation at mcp.idfkit.com.

3. walkererik1991/energyplus-idf-mcp-server#

This Python MCP server offers 35 structured MCP tools similar to the LBNL version, with support for both stdio and streamable HTTP transport. It includes HVAC topology inspection and interactive visualizations, making it particularly useful for HVAC engineers. Docker deployment is available, and the project is licensed under GPL-3.0 with 38 GitHub stars.

4. Other Options and Comparisons#

A fourth option, felixugscooper6739/energyplus-building-server, offers a similar toolset with 10 stars. Beyond EnergyPlus specifically, PowerMCP (192 stars) demonstrates the broader trend of MCP adoption in energy simulation, covering PowerWorld, PSSE, and OpenDSS for power system analysis.

How to Set Up EnergyPlus MCP Server (Step-by-Step)#

Prerequisites#

Before setting up an EnergyPlus MCP server, ensure you have:

  • Docker installed (recommended path) or Python 3.10+
  • An MCP-compatible client (Claude Desktop, VS Code with Cline, or Cursor)
  • Basic familiarity with building energy modeling concepts
  • At least 4 GB of RAM for running EnergyPlus simulations

Option A: Docker Setup (Recommended)#

Docker is the simplest and most reliable deployment method. Both LBNL EnergyPlus-MCP and idfkit-mcp offer Docker images with EnergyPlus pre-installed.

For LBNL EnergyPlus-MCP:

docker pull ghcr.io/lbnl-eta/energyplus-mcp:latest
docker run -p 8000:8000 ghcr.io/lbnl-eta/energyplus-mcp:latest

For idfkit-mcp:

docker pull ghcr.io/idfkit/idfkit-mcp:latest
docker run -p 8000:8000 ghcr.io/idfkit/idfkit-mcp:latest

Option B: pip/uv Installation#

idfkit-mcp supports direct Python installation:

pip install idfkit-mcp
# or with uv
uv add idfkit-mcp

Then start the server:

idfkit-mcp --transport sse --port 8000

Option C: Local Development Setup#

For the LBNL server from source:

git clone https://github.com/LBNL-ETA/EnergyPlus-MCP.git
cd EnergyPlus-MCP
pip install -r requirements.txt
python -m energyplus_mcp

Configuring MCP Clients#

Claude Desktop Configuration#

Add to your Claude Desktop configuration file (claude_desktop_config.json):

{
  "mcpServers": {
    "energyplus": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "ghcr.io/lbnl-eta/energyplus-mcp:latest"]
    }
  }
}

VS Code Configuration#

For VS Code with the Cline extension, add to your MCP settings:

{
  "mcpServers": {
    "energyplus": {
      "command": "docker",
      "args": ["run", "-i", "--rm", "ghcr.io/idfkit/idfkit-mcp:latest"]
    }
  }
}

Cursor Configuration#

Cursor supports MCP servers natively. Configure via Cursor settings → MCP Servers → Add New, pointing to your running server endpoint.

Essential MCP Tools and Workflows#

Loading and Inspecting Models#

Both major MCP servers provide tools to load EnergyPlus models from files or strings. Once loaded, you can inspect the model structure — list all zones, view construction assemblies, examine HVAC loops, and check simulation parameters. The get_model_summary tool (LBNL) or list_objects tool (idfkit) gives you a high-level overview of the entire model.

Modifying Building Parameters#

Modification tools let you change virtually any EnergyPlus object. Common operations include:

  • Adjusting wall, roof, and floor constructions (R-values, material layers)
  • Changing window sizes and glazing properties
  • Modifying HVAC system parameters (setpoints, efficiencies, schedules)
  • Adding or removing thermal zones
  • Updating internal loads (lighting, equipment, occupancy)

Each modification is validated before being applied, preventing invalid EnergyPlus models.

Running Simulations#

Simulation tools handle the full workflow: writing the modified model to an IDF file, running EnergyPlus with the appropriate weather file, and collecting results. The server manages temporary files, error handling, and result parsing automatically. Typical simulation time for a medium-sized commercial building model is 30–90 seconds.

Visualizing Results#

Results visualization is where MCP servers truly shine. Available visualizations include:

  • Energy consumption breakdowns (end-use pie charts)
  • Monthly load profiles (heating, cooling, lighting, equipment)
  • Zone temperature time series
  • HVAC system performance curves
  • Geometry views with color-coded thermal zones
  • Schedule heatmaps for occupancy, lighting, and equipment

These are generated as interactive Plotly charts or matplotlib figures, viewable directly in the MCP client.

Advanced Use Cases#

Autonomous Building Optimization with LLM Agents#

The most exciting application of EnergyPlus MCP servers is autonomous building optimization. The EcoLoop project demonstrated 8.5% HVAC energy savings by implementing closed-loop control: an LLM agent monitors building conditions, proposes EnergyPlus parameter changes via MCP tools, runs simulations to evaluate impact, and deploys the optimal configuration. This cycle runs continuously, adapting to weather, occupancy, and utility rates.

The AegisOS multi-agent system pushed this further, achieving 58.24% energy reduction. Their architecture uses specialized agents — a monitoring agent tracks real-time conditions, an optimization agent explores EnergyPlus parameter space via MCP, and a deployment agent applies changes to the physical building system. The MCP server acts as the critical bridge between the AI reasoning layer and the simulation engine.

HVAC System Analysis and Visualization#

HVAC engineers can use MCP servers to rapidly analyze system performance. The energyplus-idf-mcp-server includes dedicated HVAC topology inspection tools that visualize air loops, water loops, and plant equipment connections. Combined with simulation tools, you can ask “what happens if I replace this constant-volume AHU with a VAV system?” and get before-and-after energy comparisons in minutes instead of hours.

Multi-Agent Energy Management Systems#

The broader energy sector is adopting MCP for multi-agent coordination. PowerMCP (192 stars) demonstrates this for power systems, and the same architectural patterns apply to building energy. A multi-agent building management system might include:

  • A weather agent that forecasts solar gain and ambient temperature
  • An occupancy agent that predicts zone usage patterns
  • An optimization agent that runs EnergyPlus simulations via MCP
  • A control agent that adjusts HVAC setpoints and schedules

Each agent communicates through MCP, creating a modular, extensible energy management platform.

Troubleshooting Common Issues#

Docker container exits immediately. Ensure you’re running with the -i flag for stdio mode or mapping port 8000 for SSE mode. Check Docker logs with docker logs <container_id>.

EnergyPlus simulation fails. Verify the weather file path is correct and the model is valid. Use the validation tools provided by the MCP server before running simulations. Common issues include missing weather files, incompatible EnergyPlus version, and invalid object references.

MCP client cannot connect. For stdio transport, ensure the command in your client configuration is correct. For SSE transport, verify the server is running and the port is accessible. Check firewall settings if connecting remotely.

Model modification errors. Some EnergyPlus objects have complex interdependencies. Use the inspection tools to understand the model structure before making changes. The idfkit-mcp server provides schema exploration to help you understand valid object configurations.

FAQ#

Q: What is an EnergyPlus MCP server? A: An EnergyPlus MCP server is a software layer that implements the Model Context Protocol to connect AI assistants with EnergyPlus building energy simulation. It exposes 30–37 structured tools for loading, inspecting, modifying, simulating, and visualizing building energy models through natural language commands.

Q: Which EnergyPlus MCP server should I choose? A: Choose LBNL EnergyPlus-MCP if you want academic credibility and a research-backed tool (published in SoftwareX 2025). Q: Do I need to install EnergyPlus separately? A: No. Both LBNL EnergyPlus-MCP and idfkit-mcp offer Docker images with EnergyPlus pre-installed. The Docker-based setup is the recommended approach and requires no manual EnergyPlus installation.

Q: Can EnergyPlus MCP servers optimize building energy automatically? A: Yes. Projects like EcoLoop (8.5% HVAC savings) and AegisOS (58.24% total energy reduction) have demonstrated autonomous building optimization using LLM agents that call EnergyPlus MCP tools to iteratively test and deploy improved building configurations.

Q: What MCP clients work with EnergyPlus MCP servers? A: All major MCP-compatible clients work, including Claude Desktop, VS Code (with Cline extension), Cursor, and MCP Inspector. Configuration typically involves adding a JSON entry pointing to the Docker container or server endpoint.
