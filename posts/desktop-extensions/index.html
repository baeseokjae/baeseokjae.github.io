Desktop Extensions for AI agents, built on the Model Context Protocol (MCP), allow tools like Claude to connect directly to local databases, file systems, APIs, and native applications through a standardized interface. Instead of requiring manual JSON configuration and developer tooling, these extensions now ship as one-click .mcpb bundles that any Claude Desktop user can install, making AI-to-native-app integration accessible to non-developers for the first time.

What Are Desktop Extensions for AI Agents?#

Desktop Extensions are packaged MCP servers that run locally on your machine and give AI agents like Claude the ability to interact with native applications and local resources. Think of them as the AI equivalent of browser extensions — but instead of extending a web browser, they extend an AI assistant’s capabilities to read files, query databases, call APIs, and control desktop software.

Anthropic introduced Desktop Extensions in June 2025 to solve a fundamental problem: while the Model Context Protocol provided a powerful standard for AI-tool communication, actually setting up an MCP server required developers to manually edit JSON configuration files, install dependencies, and manage runtime environments. Desktop Extensions package everything — server code, dependencies, and configuration — into a single distributable file that installs with one click.

The core idea is simple: any native application that exposes an API, a command-line interface, or a data source can be wrapped in an MCP server and packaged as a Desktop Extension. Once installed, Claude can discover the extension’s capabilities — its tools, resources, and prompts — and use them autonomously to accomplish tasks.

Understanding the Model Context Protocol (MCP)#

The Model Context Protocol is the foundation on which Desktop Extensions are built. MCP is an open standard developed by Anthropic that defines how AI applications communicate with external tools and data sources. It follows a client-server architecture with three core primitives:

PrimitiveDescriptionExample
ResourcesFile-like data that can be read by the AIDatabase records, file contents, API responses
ToolsFunctions the AI can call to take actionsSend an email, create a file, run a query
PromptsPre-written templates for common tasks“Summarize this document”, “Analyze this dataset”

MCP servers can use two transport mechanisms. STDIO transport is used for local servers that run as child processes of the AI client — the server communicates via standard input and output. Streamable HTTP transport is used for remote servers that the AI client connects to over a network. For Desktop Extensions, STDIO transport is the standard approach since the server runs on the user’s local machine.

The MCP lifecycle follows a clear sequence: initialization (capability negotiation), tool discovery (the client asks what tools the server provides), tool execution (the client calls a specific tool), and notifications (the server can inform the client of capability changes). This standardized handshake means any MCP-compatible client can work with any MCP server without custom integration code.

The Evolution from Manual Setup to One-Click Installation#

Before Desktop Extensions, setting up an MCP server for Claude was a multi-step process that required significant developer knowledge. Users had to:

  1. Write or find an MCP server implementation
  2. Install all required dependencies (Node.js packages, Python libraries, etc.)
  3. Manually edit Claude’s claude_desktop_config.json file with the correct server command and arguments
  4. Manage runtime environments and ensure the correct Python or Node.js version was available
  5. Debug configuration errors with no standardized error reporting

This workflow effectively limited MCP adoption to developers. A non-technical user who wanted Claude to interact with their local calendar or file system had no practical way to set it up.

Desktop Extensions changed this entirely. The .mcpb (MCP Bundle) format — originally introduced as .dxt and renamed in September 2025 — is a ZIP archive that contains everything needed to run the server: a manifest.json file with metadata and configuration, the server code itself, and all bundled dependencies for Node.js or Python runtimes. Installing an extension is as simple as double-clicking the .mcpb file or dragging it into Claude Desktop.

This shift from manual configuration to one-click installation mirrors the evolution of browser extensions. Just as browser extensions transformed the web by making it extensible by anyone, Desktop Extensions promise to transform AI agents by making them extensible to any native application.

How Desktop Extensions Work — The .mcpb Format Explained#

A Desktop Extension is packaged as a .mcpb file, which is technically a standard ZIP archive with a specific internal structure. When you open a .mcpb file, you’ll find:

extension.mcpb
├── manifest.json          # Metadata and configuration
├── server.js              # Server implementation (Node.js)
│   or
├── server.py              # Server implementation (Python)
└── node_modules/          # Bundled Node.js dependencies
    └── ...

The manifest.json file is the heart of the extension. It contains:

  • name: A human-readable name for the extension
  • version: Semantic version number
  • description: What the extension does
  • runtime: Either node or python, specifying which runtime the server requires
  • entry: The path to the server entry point file
  • tools: An optional list of tool names the server exposes (for discovery optimization)
  • permissions: An optional array of permissions the extension requests (filesystem access, network access, etc.)

When Claude Desktop loads a .mcpb file, it extracts the archive to a secure directory, reads the manifest, spawns the server process using the specified runtime, and establishes an MCP connection via STDIO transport. The entire process takes seconds and requires no user intervention beyond the initial installation.

Step-by-Step: Building Your First MCP Server#

Let’s build a practical MCP server that gives Claude the ability to read and search local files. This example uses the Python MCP SDK (version 1.2.0 or later, Python 3.10+ required).

Step 1: Install the MCP SDK

pip install "mcp>=1.2.0"

Step 2: Create the server

# server.py
from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent
import os
import glob

app = Server("file-explorer")

@app.list_tools()
async def list_tools() -> list[Tool]:
    return [
        Tool(
            name="search_files",
            description="Search for files by pattern in a directory",
            inputSchema={
                "type": "object",
                "properties": {
                    "pattern": {"type": "string", "description": "Glob pattern (e.g., '*.py')"},
                    "directory": {"type": "string", "description": "Directory to search"}
                },
                "required": ["pattern", "directory"]
            }
        ),
        Tool(
            name="read_file_content",
            description="Read the contents of a file",
            inputSchema={
                "type": "object",
                "properties": {
                    "path": {"type": "string", "description": "Absolute path to the file"}
                },
                "required": ["path"]
            }
        )
    ]

@app.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    if name == "search_files":
        pattern = arguments["pattern"]
        directory = arguments["directory"]
        matches = glob.glob(os.path.join(directory, pattern), recursive=True)
        return [TextContent(type="text", text="\n".join(matches[:50]))]
    elif name == "read_file_content":
        path = arguments["path"]
        try:
            with open(path, "r") as f:
                content = f.read()
            return [TextContent(type="text", text=content[:10000])]
        except Exception as e:
            return [TextContent(type="text", text=f"Error: {str(e)}")]

if __name__ == "__main__":
    import anyio
    anyio.run(stdio_server, app)

Step 3: Test the server locally

python server.py

The server will start and wait for MCP messages on STDIO. You can test it with the MCP Inspector tool or by configuring it in Claude Desktop’s JSON config temporarily.

Important STDIO rule: MCP servers using STDIO transport must never write to stdout for logging or debugging purposes. All logging must go to stderr. Writing to stdout corrupts the MCP message protocol and will cause connection failures.

Packaging Your Server as a Desktop Extension#

Once your MCP server is working, packaging it as a .mcpb Desktop Extension is straightforward.

Step 1: Create the manifest.json

{
  "name": "File Explorer",
  "version": "1.0.0",
  "description": "Search and read files on the local filesystem",
  "runtime": "python",
  "entry": "server.py",
  "tools": ["search_files", "read_file_content"],
  "permissions": ["filesystem:read"]
}

Step 2: Bundle dependencies

For Python-based extensions, you need to include all dependencies. The recommended approach is to use a virtual environment and pip install into the bundle directory:

mkdir bundle
cp server.py bundle/
pip install mcp -t bundle/

For Node.js extensions, simply copy the node_modules directory alongside your server file.

Step 3: Create the .mcpb archive

cd bundle
zip -r ../file-explorer.mcpb .

That’s it. The resulting file-explorer.mcpb can be distributed to any Claude Desktop user. They simply double-click the file or drag it into Claude Desktop to install.

Installing and Testing Your Extension in Claude Desktop#

Installing a Desktop Extension in Claude Desktop is designed to be frictionless:

  1. Double-click the .mcpb file — Claude Desktop will open and prompt you to confirm installation
  2. Drag the file into Claude Desktop — drop it anywhere in the window
  3. Use the Extensions panel — open Claude Desktop’s settings, navigate to Extensions, and click “Install from file”

Once installed, the extension appears in Claude’s extension list. You can verify it’s working by asking Claude a question that requires the extension’s capabilities. For our File Explorer example:

“Search for all Python files in my Documents folder and tell me what each one does.”

Claude will discover the search_files and read_file_content tools from the extension and use them to fulfill your request. The entire interaction is transparent — Claude handles the tool discovery and execution automatically.

To manage installed extensions, open Claude Desktop’s Extensions panel where you can view all installed extensions, enable or disable them individually, and remove extensions you no longer need. Disabled extensions remain installed but are not loaded by Claude, preserving their configuration for future use.

Connecting Claude to Local Databases, File Systems, and APIs#

Desktop Extensions unlock a wide range of practical integrations. Here are three common patterns:

Local Database Integration#

An MCP server wrapping a SQLite database gives Claude the ability to query, analyze, and visualize data directly. The server exposes tools like run_query, list_tables, and get_schema. Claude can then answer questions like “What were our top-selling products last quarter?” by running SQL queries against your local database.

File System Operations#

Beyond simple file reading, a file system extension can provide tools for file organization, batch renaming, content search across thousands of documents, and automated file conversion. This turns Claude into a powerful file management assistant that can organize your Downloads folder, rename photos by date, or find documents containing specific phrases.

API Wrappers#

Any REST API can be wrapped in an MCP server. A GitHub extension might expose tools for listing issues, creating pull requests, and reviewing code. A calendar extension might allow Claude to check your schedule, create events, and find free time slots. A weather extension could provide real-time forecasts and alerts.

The key advantage of Desktop Extensions over direct API calls is that Claude handles tool discovery and selection automatically. You don’t need to tell Claude which API endpoint to call or how to format the request — the extension’s manifest tells Claude what tools are available, and Claude chooses the right one based on your natural language request.

Security Considerations and Best Practices#

Desktop Extensions introduce significant security considerations that every user and developer should understand. Because extensions run as local processes with access to the user’s file system and network, they represent a powerful attack surface.

The LayerX Vulnerability#

In February 2026, security researchers at LayerX discovered a critical vulnerability in Claude Desktop Extensions that earned a CVSS score of 10/10 — the maximum severity rating. The attack exploited a zero-click remote code execution vector through the Google Calendar connector. Claude processes input from public-facing connectors and autonomously decides which MCP connectors to invoke. By crafting malicious calendar events, attackers could trick Claude into executing commands through extensions with command-line access, even though the initial entry point was a seemingly low-risk connector like Calendar.

Anthropic reportedly opted not to address the vulnerability, raising concerns about the company’s approach to extension security. This incident highlights a fundamental architectural challenge: when an AI agent has the autonomy to invoke tools based on external input, every input source becomes a potential attack vector.

The Native Messaging Bridge Controversy#

Privacy researchers have also raised concerns about Claude Desktop’s behavior during installation. According to an investigation by That Privacy Guy, Claude Desktop silently registers a Native Messaging host in Chromium-based browsers (Brave, Chrome, and others) without informing the user or asking for consent. The native messaging configuration file is installed at ~/Library/Application Support/BraveSoftware/Brave-Browser/NativeMessagingHosts/com.anthropic.claude_browser_extension.json on macOS, and it pre-authorizes three Chrome extension IDs to communicate with a binary outside the browser sandbox.

This means that Claude Desktop can bridge between the browser and the desktop environment without the user’s explicit knowledge — a capability that could be used to read browser content, interact with web pages, or exfiltrate data across the browser-desktop boundary.

Best Practices for Safe Extension Use#

Given these security concerns, here are essential best practices:

PracticeWhy It Matters
Install extensions only from trusted sourcesMalicious .mcpb files can access your file system and network
Review manifest permissionsCheck what permissions an extension requests before installing
Disable extensions you don’t useReduces the attack surface of unused connectors
Run extensions in isolated environmentsConsider using containerized or sandboxed runtimes for sensitive work
Monitor extension behaviorWatch for unexpected file access or network connections
Keep extensions updatedSecurity patches may address discovered vulnerabilities
Audit extension permissions regularlyReview which extensions have filesystem, network, or command execution access

Anthropic has stated that extensions run with the same privileges as the Claude Desktop process itself. According to LayerX, extensions run without sandboxing with full system privileges. This means a compromised extension has the same access as any application you run on your desktop — it can read your files, access your network, and execute commands.

The Future of Desktop Extensions for AI Agents#

Desktop Extensions represent a pivotal moment in the evolution of AI agents. They solve a real problem — making AI-tool integration accessible to non-developers — but they also introduce new security and privacy challenges that the industry has not yet fully addressed.

Several trends will shape the future of this technology:

Standardized sandboxing: The LayerX vulnerability and Native Messaging controversy will likely push toward mandatory sandboxing for extensions. Future versions of the .mcpb format may include required permission declarations and runtime isolation guarantees.

Extension marketplaces: Just as browser extensions have app stores, Desktop Extensions will likely develop curated marketplaces with security review processes. Anthropic has hinted at a Claude Extension Directory that would provide vetted, signed extensions.

Cross-platform standardization: While Desktop Extensions currently focus on Claude Desktop, the MCP protocol is platform-agnostic. We can expect extensions to work across different AI agents and platforms, creating an ecosystem similar to how browser extensions work across Chrome, Firefox, and Edge.

Enterprise management: Organizations will need tools to manage, approve, and audit Desktop Extensions across their workforce. Enterprise extension management — including allowlists, blocklists, and audit logging — will become a critical capability.

Improved permission models: Future extensions will likely support granular, user-approvable permissions similar to mobile app permissions. Instead of all-or-nothing installation, users might approve specific capabilities at runtime.

Desktop Extensions for AI agents are still in their early stages, but they represent a fundamental shift in how we think about AI integration. By making it possible for anyone to extend an AI agent’s capabilities to native applications, they open the door to a new generation of AI-powered workflows — provided the security and privacy challenges can be adequately addressed.

Frequently Asked Questions#

Q: What is a Desktop Extension for AI agents?

A: A Desktop Extension is a packaged MCP server that gives AI agents like Claude the ability to interact with native applications and local resources. It’s distributed as a .mcpb file that installs with one click, containing server code, dependencies, and configuration.

Q: Do I need to be a developer to install Desktop Extensions?

A: No. Desktop Extensions are designed for non-developers. Installing one requires only double-clicking a .mcpb file or dragging it into Claude Desktop. Building your own extension does require programming knowledge, but using pre-built extensions is straightforward.

Q: Are Desktop Extensions secure?

A: Security is an active concern. Extensions run with the same privileges as Claude Desktop and are not sandboxed. A critical vulnerability (CVSS 10/10) was discovered in February 2026 involving zero-click RCE through the Google Calendar connector. Only install extensions from trusted sources and review their requested permissions.

Q: What’s the difference between MCP and Desktop Extensions?

A: MCP (Model Context Protocol) is the underlying standard that defines how AI agents communicate with tools and data sources. Desktop Extensions are a packaging and distribution format (.mcpb) that makes MCP servers installable with one click. MCP is the protocol; Desktop Extensions are the distribution mechanism.

Q: Can Desktop Extensions work with AI agents other than Claude?

A: Yes. MCP is an open protocol, and any MCP-compatible client can use MCP servers. While Desktop Extensions (.mcpb files) were introduced by Anthropic for Claude Desktop, the underlying MCP servers can be configured to work with any MCP-compatible AI agent.
