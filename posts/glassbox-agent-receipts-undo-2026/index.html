What Is Glassbox for AI Agents and Why Do You Need Receipts and Undo Capabilities?#

Glassbox refers to a growing ecosystem of tools and protocols that bring full execution transparency to autonomous AI agents — recording every shell command, file change, API call, and decision in a tamper-evident audit trail. Agent receipts are cryptographically signed records of those actions, and safe undo is the ability to reverse them with verifiable proof. As AI agents take on more autonomous responsibilities in production, the combination of glass-box visibility, cryptographic receipts, and reversible actions has shifted from a competitive differentiator to a compliance necessity in 2026.

What Is Glassbox? — Two Meanings, One Trend#

The term “glassbox” in the AI agent space carries two distinct but complementary meanings. On one side, Glassbox.build is a commercial SaaS platform that provides execution visibility for AI agents running on developer machines. On the other, the broader glass-box paradigm refers to the architectural principle of making every agent action observable, auditable, and reversible — in contrast to the traditional “black box” where agents produce outputs without any transparent record of how they arrived there.

Both interpretations converge on the same insight: as AI agents graduate from experimental toys to production tools that modify files, execute commands, call APIs, and spend money, the lack of visibility into their actions becomes an unacceptable operational and compliance risk. The glass-box movement is the industry’s response to that risk, and 2026 is the year it went mainstream.

Glassbox.build — Commercial Execution Visibility for AI Agents#

Glassbox.build is a Sydney-based startup currently in preview mode that offers a SaaS platform for recording and reviewing every action taken by AI agents on developer machines. It supports multiple agent frameworks including Claude Code, OpenClaw, Hermes, and Codex, making it framework-agnostic by design.

Core Features: CMD_LOG, FILE_DIFF, TOOL_USE#

Glassbox.build organizes agent visibility into three core data streams:

CMD_LOG captures every shell command the agent executes, along with its exit code, timestamps, and output. This gives developers a complete terminal replay of what the agent did, making it possible to audit command execution without trusting the agent’s own self-reporting.

FILE_DIFF records every file change the agent makes, showing before-and-after diffs. When an agent modifies configuration files, source code, or deployment scripts, FILE_DIFF provides a clear, line-by-line record of what changed and when.

TOOL_USE tracks every MCP tool call, web fetch, and API hit the agent makes. This is particularly important for agents that interact with external services — every API call is logged with its parameters and response, creating a complete chain of external interactions.

Pricing and Target Audience#

Glassbox.build offers early bird pricing at $15 per month for three machines with unlimited agents. This aggressive pricing targets individual developers and small teams who want agent visibility without enterprise overhead. The platform is designed for developers who run multiple agent frameworks across several machines and need a centralized dashboard to review agent actions after the fact.

The primary limitation is that Glassbox.build is a post-hoc observation tool — it records what happened but does not provide cryptographic guarantees of integrity or a standardized format for sharing audit records across organizations.

Agent Receipts Protocol — The Open Standard for Cryptographic Audit Trails#

The Agent Receipts Protocol (ARP), developed by Obsigna and currently at v0.4.0 (May 2026), is an open standard for creating cryptographic audit trails of AI agent actions. Unlike Glassbox.build’s centralized SaaS approach, ARP is a protocol specification with multiple implementations, designed to be interoperable across different agent frameworks, organizations, and compliance regimes.

How Agent Receipts Work: W3C Verifiable Credentials + Ed25519 + Hash Chain#

Each agent receipt is a W3C Verifiable Credential with the type AgentReceipt, signed using Ed25519 cryptographic keys. The receipt captures five essential dimensions of every agent action:

  1. Who — the agent identity and the human authorizer who approved the action
  2. What — the action type (file write, command execution, API call, payment) and its risk level
  3. When — precise timestamps for initiation, execution, and completion
  4. Outcome — success, failure, pending, or reversible status
  5. Chain position — the receipt’s position in a hash chain that makes tampering evident

Receipts are hash-chained into a tamper-evident log, meaning each receipt includes the hash of the previous receipt. Altering any past receipt breaks the chain for all subsequent entries, providing strong cryptographic guarantees of integrity. Parameters are hashed rather than stored in plaintext, preserving privacy while maintaining auditability.

The Out-of-Agent Audit Boundary (obsigna-daemon)#

One of the most architecturally significant features of the Agent Receipts Protocol is the out-of-agent audit boundary. Signing keys live in a separate daemon process (obsigna-daemon) that runs outside the agent’s process space. This means that even if an agent is compromised — through prompt injection, malicious tool output, or a supply chain attack — the attacker cannot forge receipts because the signing key is never accessible to the agent process itself.

This separation is critical for compliance. A receipt signed by a key that lived inside the agent process provides no real security guarantee, because a compromised agent could sign fraudulent receipts. By keeping the signing key in a separate, hardened daemon, ARP ensures that receipts remain trustworthy even when the agent itself is not.

SDKs, MCP Proxy, and Ecosystem Tooling#

The Agent Receipts Protocol ships with SDKs for Go, TypeScript, and Python, making it straightforward to integrate into existing agent frameworks. An MCP proxy intercepts tool calls and automatically generates receipts, providing drop-in auditability without modifying agent code. A Hook for Claude Code adds receipt generation to Claude Code sessions, and a Dashboard provides a web interface for browsing and verifying receipts.

The protocol has seen rapid adoption. Between April and May 2026, signed hash-chained receipts went from a differentiator to table stakes, now adopted by Asqav, nono, Pipelock, and Microsoft AGT (Agent Governance Toolkit). Microsoft AGT v3.0 Public Preview now ships first-class Agent Framework integration with a compliance pipeline that consumes Agent Receipts natively.

Open Source GlassBox AI — Structural Accountability in Orchestration#

The open source GlassBox AI project by Agentic Trust Labs takes a fundamentally different approach. Rather than adding a visibility layer on top of existing agents, it builds accountability into the orchestration layer itself.

State Machine Engine with Append-Only Audit Trail#

GlassBox AI runs agents as state machines with explicit, traceable transitions. The engine itself is remarkably compact — approximately 260 lines of core code — with agents implemented as plain functions that return events. The audit trail is append-only and always on; it cannot be disabled or configured away. This design choice reflects a philosophy that accountability should be a structural property of the system, not an optional feature.

Native HITL and Human Correction Feedback Loop#

Human-in-the-loop (HITL) is a first-class pause state in GlassBox AI. When the engine encounters a high-risk action or an approval threshold, it pauses, waits for human input, and resumes with full context. Human corrections are fed back into the system as version-controlled RULES.md files and searchable episodes.jsonl logs, creating a continuous improvement loop where human oversight directly shapes agent behavior over time.

The trade-off is maturity. GlassBox AI is explicitly not production-ready — it is an early-stage project that demonstrates the structural accountability approach rather than a polished product.

Leviathan Glassbox — Enterprise Agent Payment and Approval Layer#

Leviathan Matrix offers an enterprise-grade Glassbox layer focused specifically on agent financial transactions. It provides agent journey replay — showing who acted, what happened, why, how much was at stake, and which checkpoint decided the action. Spend authority controls include maximum budgets, approval thresholds, and duplicate-payment protection.

Approval binding is a key feature: it cryptographically binds human approval to stable action fingerprints, ensuring that what was approved is exactly what was executed. Agent Receipts in Leviathan’s system include intent, policy, approval, execution evidence, outcome, and audit hash. The platform sits above payment providers, wallets, and API networks — it does not custody funds but provides the transparency and control layer for agent-initiated financial actions.

The Regulatory Landscape: EU AI Act and the August 2026 Deadline#

The EU AI Act, with enforcement for high-risk AI systems beginning August 2, 2026, is the primary regulatory forcing function driving agent auditability adoption. The Act mandates traceability for high-risk AI systems, requiring that organizations maintain records of system outputs, decisions, and the data used to make them.

For organizations deploying AI agents in regulated domains — financial services, healthcare, legal, HR, insurance — the EU AI Act creates a concrete compliance obligation. Without an audit trail that cryptographically proves what an agent did, when, and who authorized it, organizations face potential penalties of up to 7% of global annual turnover or €35 million, whichever is higher.

The timing is significant. The Agent Receipts Protocol reached v0.4.0 in May 2026, just three months before the EU AI Act enforcement deadline. This is not a coincidence — the protocol was designed with regulatory compliance as a primary use case, and its rapid adoption reflects the market’s recognition that agent auditability is no longer optional.

The Future: Reversal Receipts and Safe Undo for AI Agents#

The Agent Receipts Protocol v0.4.0 introduces a concept that may define the next phase of agent governance: reversal receipts. A reversal receipt is a cryptographically signed record proving that a previous agent action was reversed. This creates a complete lifecycle for agent actions: initiation, execution, verification, and (if needed) reversal, all with cryptographic proof.

Safe undo for AI agents is the practical application of reversal receipts. When an agent makes a change that needs to be rolled back — a file modification, a database update, a configuration change — the reversal receipt provides cryptographic evidence that the undo actually happened. This is particularly important in regulated environments where auditors need to see not just what went wrong, but what was done to fix it.

The technical challenge of safe undo goes beyond simple version control. Agent actions often have side effects — a file change triggers a deployment, an API call updates a customer record, a payment initiates a transfer. Reversing the primary action may not fully reverse the side effects. Reversal receipts address this by recording the scope and completeness of the reversal, making the limitations transparent to auditors.

Conclusion — Why 2026 Is the Year of Agent Auditability#

The convergence of three forces makes 2026 the year agent auditability went from optional to essential. First, the EU AI Act enforcement deadline in August 2026 creates a hard compliance deadline for organizations deploying AI agents in high-risk domains. Second, the maturation of the Agent Receipts Protocol to v0.4.0 provides a standardized, cryptographically sound foundation for agent audit trails. Third, the rapid adoption of signed hash-chained receipts by major platforms — Microsoft AGT, Asqav, nono, Pipelock — signals that the industry has converged on a standard.

The glass-box paradigm shift is not about any single tool. It is about the recognition that as AI agents become more autonomous and more capable, the ability to see, verify, and reverse their actions is not a nice-to-have feature — it is a fundamental requirement for safe deployment. Whether you choose Glassbox.build for developer visibility, the Agent Receipts Protocol for cryptographic compliance, open source GlassBox AI for architectural exploration, or Leviathan Glassbox for enterprise financial controls, the direction is clear: the black box is closing, and the glass box is opening.

Frequently Asked Questions#

What is a glassbox AI agent receipt?#

A glassbox AI agent receipt is a cryptographically signed record of an agent action, typically formatted as a W3C Verifiable Credential. It captures who performed the action, what was done, when it happened, the outcome, and its position in a tamper-evident hash chain. Receipts provide verifiable proof that an agent took a specific action, enabling auditability and compliance.

How does safe undo work for AI agents?#

Safe undo for AI agents uses reversal receipts — cryptographically signed records that prove a previous agent action was reversed. The Agent Receipts Protocol v0.4.0 introduced reversal receipts as a standard, allowing organizations to demonstrate to auditors not just what went wrong, but what was done to fix it, with cryptographic evidence.

What is the difference between Glassbox.build and the Agent Receipts Protocol?#

Glassbox.build is a commercial SaaS platform that records agent actions (shell commands, file diffs, tool calls) in a centralized dashboard for developer visibility. The Agent Receipts Protocol is an open standard for cryptographic audit trails that provides tamper-evident, signed receipts. They are complementary: Glassbox.build provides the visibility, while ARP provides the cryptographic guarantees.

Do I need agent audit trails for EU AI Act compliance?#

Yes, if you deploy AI agents in high-risk domains such as financial services, healthcare, legal, or HR. The EU AI Act, with enforcement beginning August 2, 2026, mandates traceability for high-risk AI systems. Cryptographic audit trails that prove what an agent did, when, and who authorized it are essential for demonstrating compliance.
