What Is LocalScore?#

LocalScore is an open-source benchmarking tool that measures how well large language models (LLMs) run on your local hardware. Developed by CJ Pais and backed by Mozilla Builders under the Apache 2.0 license, it provides a standardized way to evaluate LLM performance across CPUs, NVIDIA GPUs, AMD GPUs, and Apple Silicon. Instead of relying on vague impressions or cloud-based benchmarks that don’t reflect your actual machine, LocalScore gives you a single numerical score — 1,000 is excellent, 250 is passable, and below 100 means a poor user experience. Built on top of Llamafile for cross-platform portability, it runs entirely offline and submits results only with your explicit consent.

Why Local LLM Benchmarks Matter#

The local AI movement is accelerating rapidly. As of mid-2026, capable small language models in the 1B to 14B parameter range can run on consumer hardware — a laptop with 8GB of RAM, a desktop with a mid-range GPU, or even an Apple Silicon MacBook. But performance varies wildly between configurations. A model that runs smoothly on an M4 Mac Mini might be unusable on an older Intel laptop with integrated graphics.

Before LocalScore, there was no standardized way to compare local LLM performance across different hardware. Cloud benchmarks like MLPerf and Chatbot Arena measure performance on enterprise-grade data center hardware — not the RTX 4060 in your gaming PC or the M3 Pro in your work laptop. LocalScore fills this gap by providing a benchmark designed specifically for consumer hardware, measuring what actually matters for local LLM users: how fast does the model start generating, how many tokens per second can it sustain, and how does it handle real-world tasks like summarization, classification, and long-form generation.

How LocalScore Works — The Three Metrics#

LocalScore combines three fundamental performance metrics into a single composite score:

Prompt Processing Speed (Tokens Per Second)#

This measures how quickly the system processes your input prompt. Higher prompt processing speed means the model can ingest large contexts — documents, conversation histories, or codebases — without noticeable delay. This metric is especially important for tasks like document analysis, RAG (retrieval-augmented generation), and multi-turn conversations where each new message must be processed against a growing context window.

Generation Speed (Tokens Per Second)#

This measures how fast the model produces new tokens after processing the prompt. Generation speed directly affects the perceived responsiveness of the model. For interactive use cases like chat, coding assistance, or creative writing, higher generation speed means a more fluid, natural interaction. For batch processing tasks like bulk text classification or data extraction, it determines overall throughput.

Time-to-First-Token (TTFT, Milliseconds)#

This measures the delay between submitting a prompt and receiving the first generated token. Low TTFT is critical for interactive applications — a model that takes several seconds to start responding feels sluggish even if its generation speed is high. LocalScore measures TTFT across multiple scenario sizes, from short 16-token classification prompts to long 3,072-token generation tasks.

The Composite Score#

These three metrics are weighted and combined into a single LocalScore. The scoring scale is designed to be intuitive:

Official Benchmark Models (Tiny, Small, Medium)#

LocalScore provides three official benchmark models, each targeting a different hardware tier:

Tiny — Llama 3.2 1B (~2GB VRAM)#

The Tiny benchmark uses Meta’s Llama 3.2 1B parameter model. It requires approximately 2GB of VRAM and is designed for low-end hardware: integrated graphics, older GPUs, and systems with limited RAM. This is the entry point for most users and provides a baseline for comparing hardware configurations. Even a laptop with 8GB of unified memory on Apple Silicon can run this benchmark comfortably.

Small — Llama 3.1 8B (~6GB VRAM)#

The Small benchmark uses Llama 3.1 8B, requiring roughly 6GB of VRAM. This targets mid-range hardware: GPUs like the NVIDIA RTX 3060 or 4060, AMD RX 6000 series, and Apple Silicon with 16GB or more unified memory. The 8B parameter class represents the sweet spot for local LLM usage in 2026 — capable enough for most tasks while still running on widely available consumer hardware.

Medium — Qwen 2.5 14B (~10GB VRAM)#

The Medium benchmark uses Qwen 2.5 14B, requiring approximately 10GB of VRAM. This targets high-end consumer hardware: NVIDIA RTX 3080/4080/4090, AMD RX 7000 series, and Apple Silicon with 24GB+ unified memory. The 14B parameter class represents the upper end of what’s practical on consumer hardware today, offering near-frontier quality for many tasks.

You are not limited to these three models. LocalScore supports any GGUF format model, so you can benchmark any model you would actually use in your workflow.

Supported Hardware and Setup#

LocalScore’s cross-platform support is one of its strongest features. Built on Llamafile, it runs on:

  • CPUs: Any modern x86 or ARM processor. Performance varies widely based on core count, architecture, and memory bandwidth.
  • NVIDIA GPUs: Full CUDA support via cuBLAS. Tested on RTX 20/30/40 series, GTX 16 series, and professional Quadro/RTX cards.
  • AMD GPUs: ROCm support for Linux and Windows. Compatible with RX 5000/6000/7000 series and Radeon Pro cards.
  • Apple Silicon: Native Metal acceleration on M1, M2, M3, and M4 series chips. Performance scales with GPU core count and unified memory.

Installation#

The CLI tool is distributed as a single executable — no Python environment, no dependency hell, no container setup. Download the appropriate binary for your platform from the GitHub releases page, make it executable, and run it. For Llamafile users, LocalScore is also integrated via the --localscore flag, so you can benchmark directly from your existing Llamafile setup.

Limitations and What’s Missing#

LocalScore is powerful but not complete. The development team has been transparent about current limitations:

  • No Ollama integration: You cannot run LocalScore through Ollama’s model management system. This is a frequently requested feature and a logical future addition.
  • Single-GPU focus: LocalScore tests single-GPU configurations only. Multi-GPU setups, tensor parallelism, and model sharding are not currently supported.
  • No speculative decoding: Techniques like speculative decoding that accelerate generation are not measured. This means LocalScore may underrepresent the real-world performance of systems using these optimizations.
  • No multi-model workflows: The benchmark tests one model at a time. Real-world workflows often chain multiple models (e.g., a small model for classification feeding into a larger model for generation).
  • No efficiency metrics: Power consumption, thermal performance, and energy efficiency are not measured. The team has announced an “efficiency score” as a planned future feature.
  • Limited scenario diversity: The nine test scenarios, while well-designed, don’t cover every real-world pattern. Vision models, audio models, and diffusion models are explicitly out of scope for now.

These limitations are not dealbreakers — they represent opportunities for community contribution and future development. The project is open source, and many of these features could be added by the community.

The Mozilla Builders Connection#

LocalScore’s association with Mozilla Builders is significant. Mozilla Builders is Mozilla’s initiative to support open-source AI projects that align with Mozilla’s mission of a healthy, open internet. Being selected as a Mozilla Builders project provides:

  • Institutional credibility: Mozilla’s brand carries weight in the open-source community. Their backing signals that LocalScore has been vetted for quality, security, and alignment with open-source values.
  • Funding and resources: Mozilla Builders provides financial support and development resources, accelerating the project’s growth.
  • Community reach: Mozilla’s network amplifies the project’s visibility, attracting more users and contributors to the benchmark database.

This backing is particularly important in the AI space, where many benchmarking tools are controlled by large corporations with commercial interests. LocalScore’s Mozilla-backed, Apache 2.0 licensed approach ensures the benchmark remains independent, transparent, and community-driven.

Who Should Use LocalScore?#

LocalScore is valuable for several distinct audiences:

Hardware buyers evaluating a new GPU, laptop, or desktop for local AI work can use LocalScore to compare real-world LLM performance before making a purchase decision. The public database of over 3,944 submissions provides a reference point for virtually any hardware configuration.

Developers building local AI applications need to understand the performance envelope of their target hardware. LocalScore helps answer questions like: “Will this model run acceptably on a MacBook Air with 16GB of RAM?” or “What’s the minimum GPU I need for real-time code completion?”

Self-hosting enthusiasts running local LLMs for privacy, cost savings, or offline access can use LocalScore to optimize their setup — comparing quantization levels, inference backends, and hardware configurations to find the best balance of speed and quality.

Researchers and writers covering the local AI ecosystem can use LocalScore data to support hardware recommendations and performance comparisons with real, reproducible data rather than anecdotal impressions.

Getting Started — Quick Setup Guide#

  1. Download the CLI: Visit the LocalScore GitHub releases page and download the binary for your operating system.
  2. Make it executable: Run chmod +x localscore on Linux/macOS.
  3. Run the benchmark: Execute ./localscore to start the default benchmark with the Tiny model (Llama 3.2 1B). The tool will automatically download the model and run all nine test scenarios.
  4. View your results: The CLI displays your LocalScore, individual metric breakdowns, and scenario-by-scenario performance.
  5. Submit (optional): Results can be submitted to the public database with a single command. Submission is anonymous and optional — all benchmarks run entirely offline.
  6. Test other models: Use ./localscore --model path/to/your/model.gguf to benchmark any GGUF model.
  7. Compare online: Browse the public database at localscore.ai/latest to see how your hardware compares to other configurations.

For Llamafile users, simply add the --localscore flag to your existing Llamafile command to run the benchmark without downloading a separate binary.

Final Verdict#

LocalScore is the closest thing the local AI community has to a “Geekbench for LLMs.” It fills a genuine gap — there was no standardized, open-source way to compare local LLM performance across consumer hardware before it. The three-metric composite score is well-designed, the nine test scenarios cover realistic usage patterns, and the public database creates a valuable network effect where every submission makes the tool more useful for everyone.

The Mozilla Builders backing and Apache 2.0 license provide confidence in the project’s long-term viability and independence. The acknowledged limitations — no Ollama integration, single-GPU focus, no speculative decoding — are real but not fatal, and the open-source nature means the community can address them over time.

If you run local LLMs or are considering hardware for local AI work, LocalScore should be your first stop for benchmarking. It’s free, it runs entirely on your machine, and it gives you actionable data about what your hardware can actually do. With over 3,944 submissions already in the database and growing, LocalScore is well on its way to becoming the standard reference point for local LLM performance.

Frequently Asked Questions#

What hardware do I need to run LocalScore?#

LocalScore runs on virtually any modern computer. The Tiny benchmark (Llama 3.2 1B) requires about 2GB of VRAM and works on integrated graphics, CPUs, and Apple Silicon. For the Small benchmark (Llama 3.1 8B), you need approximately 6GB of VRAM. The Medium benchmark (Qwen 2.5 14B) requires about 10GB of VRAM. All benchmarks also run on CPU-only systems, though performance will be significantly lower.

Is LocalScore free to use?#

Yes, LocalScore is completely free and open source under the Apache 2.0 license. There are no paid tiers, no subscription fees, and no usage limits. You can download the CLI, run unlimited benchmarks, and submit results to the public database at no cost.

Does LocalScore work on Apple Silicon?#

Yes, LocalScore has native support for Apple Silicon (M1, M2, M3, and M4 series) via Metal acceleration. Apple Silicon systems typically perform very well on LocalScore benchmarks due to their unified memory architecture, which eliminates the PCIe bottleneck between CPU and GPU.

Can I benchmark any model, or only the official ones?#

You can benchmark any model in GGUF format. While LocalScore provides three official benchmark models (Tiny, Small, Medium) for standardized comparison, you can use the --model flag to point to any GGUF file on your system. This lets you test the specific models you plan to use in your workflow.

How does LocalScore protect my privacy?#

All benchmarks run entirely on your local machine with no data transmitted anywhere. Submission to the public database is completely optional and anonymous — you must explicitly opt in with a separate command. No system information, IP addresses, or identifying data is collected without your consent.
