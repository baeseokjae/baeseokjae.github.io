## Orbit AI — CRO-Trained Intelligence for Page Optimization

Orbit AI is the intelligence layer that powers UXON's page generation and optimization workflows. Unlike generic AI content generators that produce text based on prompts alone, Orbit AI is specifically trained on conversion rate optimization (CRO) principles.

### How Orbit AI Works

When a user or AI agent instructs Orbit AI to create a landing page, it considers:

- **Brand intelligence**: Market context about the business, its competitors, and positioning before drafting any content
- **Review intelligence**: Analysis of customer reviews and testimonials to extract authentic claims and proof themes
- **CRO best practices**: Layout, copy, and call-to-action placement optimized for conversion based on proven patterns
- **Historical performance**: Data from previous A/B tests to inform new page variations

This CRO-trained approach means Orbit AI doesn't just generate pages — it generates pages that are statistically more likely to convert. For agencies managing multiple client accounts, this reduces the time spent on manual optimization while maintaining or improving conversion rates.

### The Skills File Approach

One of UXON's most innovative features is the **skills file** system. When setting up an MCP connection, users define a skills file that gives AI agents a controlled command layer. This file specifies:

- Which API keys the agent can access
- What actions the agent is permitted to perform (create pages, run experiments, view analytics)
- Brand context and market positioning data
- Review intelligence for authentic copy generation

For agencies, this skills file approach is critical for compliance. It ensures that AI agents operating on behalf of different clients stay within their designated boundaries and cannot access data or perform actions outside their scope.

## Cross-Domain A/B Testing — A Rare and Powerful Feature

Most landing page builders limit A/B testing to pages hosted on their own platform. UXON breaks this limitation with **cross-domain A/B testing** — the ability to test any page against any other page, even when they live on different domains.

### Why Cross-Domain Testing Matters

Consider a typical AI ad campaign workflow:

1. An AI agent creates a landing page on UXON for a Google Ads campaign
2. The marketer already has a high-performing page on their main website
3. With cross-domain testing, they can run the UXON page against the existing website page in a single experiment
4. The winner is determined by actual conversion data, not platform bias

This capability is particularly valuable for agencies running campaigns across multiple client domains. Instead of migrating all pages to a single platform, they can test UXON-optimized pages against existing infrastructure and make data-driven decisions about where to invest.

## First-Party Attribution — Solving the Post-Click Reporting Gap

AI ad campaigns create a unique reporting challenge. When AI agents generate and serve ads across multiple platforms, tracking what happens after a click becomes fragmented. UXON addresses this with a **first-party attribution pixel** that provides post-click reporting directly within the platform.

### How First-Party Attribution Works

The attribution pixel fires when a visitor lands on a UXON-hosted page, capturing:

- Source of the click (ad platform, campaign, ad creative)
- User behavior on the landing page
- Conversion events and their value
- Cross-session activity

This data feeds back into Orbit AI, creating a closed loop where conversion data informs future page generation and optimization. For agencies, this means they can report on campaign performance without relying on third-party cookies or platform-specific analytics that may undercount conversions.
